# DAO Participation Lab

このフォルダは、Next Being Labの実験の一環として、AI時代の「小さな社会参加」を試すための、5〜10人規模の実験共同体の初期設計書です。

ここでいうDAOは、トークンやオンチェーン運用を前提にした仕組みではなく、少人数が分散的に提案し、試し、振り返るための運営様式を指します。

## この実験でいうDAOとは何か

この実験でいうDAOは、次の条件を満たす小さな共同運営の方法です。

- 特定の上司や中央管理者だけに依存せず、参加者が提案し、試し、記録し、見直せる
- 役割はあるが、役割が恒久的な支配権にならない
- ルールは固定憲法ではなく、限定範囲で試して更新できる
- 参加、休止、退出を本人の意思で決められる
- AIは運営負荷を下げる補助として使うが、責任は人が持つ

言い換えると、DAOは「みんなで全部を決める理想社会」ではありません。少人数が、中央集権と無秩序の間にある運営方法を持つための実務上の型です。

この実験では、次のものをDAOとはみなしません。

- トークン保有で権利が決まる仕組み
- 自動化すれば公平になるという発想
- 法人格や雇用責任の代替
- 生活保障や福祉配分の判断装置

## DAOは何のために使うか

この実験でDAOを使う目的は、少人数でも「参加の入口」「提案の流れ」「やめやすさ」を同時に扱える運営方法を持つことです。

特に、次の課題に対して使います。

- 常時フル参加できない人でも関われるようにする
- 一人の善意や過労に依存せず、運営の持ち回りを可能にする
- 小さな提案を、重い会議や強い上下関係なしで試せるようにする
- AIを使って記録や叩き台作成の負担を軽くする
- 参加しない自由や退出の自由を制度として守る

加えて、NBLの試作品や公開前コンテンツに対して、任意参加でフィードバックを返すための「小さなレビュー共同体」としても使います。

## NBLでの具体的な利用イメージ

このDAO実験は、たとえば次のような用途に使えます。

- JACのプロトタイプに対する感想、違和感、使いづらさの収集
- NBLサイト上の文章、案内、説明導線へのフィードバック
- 新しい実験ページや公開前ドラフトへの事前レビュー
- AIが作った下書きに対する、人による読みやすさや安全性の確認

ただし、このDAOは「NBLの正式意思決定機関」ではありません。

- 集めるのは、意見、懸念、利用感、改善案
- 決めるのは、各プロトタイプやコンテンツの責任者
- DAO参加者の所見は参考情報であり、採否を自動で決めるものではない

したがって、ここでの役割は `NBLを代表して決定する人` ではなく、`NBLの試作に伴走してフィードバックする人` として位置付けます。

## DAOが向いている場面

この方式は、次のような場面に向いています。

- 正解がまだなく、小さく試して学ぶ必要がある
- 参加濃度が人によって異なる
- 一部の人だけで先に試し、後で共有できる
- 失敗しても戻せる範囲で進められる
- 成果よりも、参加のしやすさや運営負荷の軽さも評価対象にしたい
- プロトタイプやコンテンツに対して、多すぎない人数で率直な反応を集めたい

## DAOが向かない場面

逆に、次のような場面には向きません。

- 生活保障、福祉、金銭配分の可否を決める場面
- 緊急対応や、即時の指揮命令が必要な場面
- 法的責任や安全責任の所在を明確に固定する必要がある場面
- 人事評価、査定、選抜、序列化を行う場面
- 大人数に一気に適用する制度設計

このDAO実験は、万能な統治モデルを作るためではなく、NBLの中で「小さな社会参加」を成立させるための限定的な運営実験として位置付けます。

## この実験の前提

- トークン、NFT、常時インセンティブ設計を前提にしない
- 参加は任意で、休止や退出はいつでも可能
- 生存保障、生活費、居場所の確保を貢献量と結びつけない
- 常時ランキング、スコア化、序列表示をしない
- 大きな理念より、12週間で試せる小さな運用を優先する
- AIは参加障壁を下げるための補助に使い、最終判断は人が持つ

## NBLでの位置付け

このDAO実験は、Next Being Labにおける参加設計の実験単位です。NBL全体のサイト構成、情報設計、見せ方の再編成は別スレッドで扱い、このフォルダでは次の範囲だけを扱います。

- 小規模DAO実験の目的、原則、運営ルール
- 最初の3か月で回す実験案
- 最初に扱うテーマ候補の整理

次の項目は、このフォルダでは扱いません。

- NBLサイト全体の再編成
- NBL全体のブランドや導線設計
- ほかの実験群との統合的な情報アーキテクチャ

## 何を試すか

この実験では、次の問いを小さく検証します。

1. 15〜60分程度の小さな関与でも、社会参加の感覚は生まれるか
2. 競争や点数化なしでも、共同体として運営できるか
3. AIを補助に使うことで、提案、記録、振り返りの負担を下げられるか
4. 退出しやすさを保ったまま、一定の継続性を持てるか

## 想定する運用イメージ

- 人数: 5〜10人
- 期間: 最初の3か月
- 接点: 非同期のテキストやり取りを基本に、隔週で短い定例を行う
- 成果物: 小さな提案、試行ログ、振り返りメモ
- 管理方法: 共有ドキュメントと単一の連絡チャネルで十分に回る設計にする

## 運営上の安全ガード

この設計は、次の条件を満たさない限り採用しません。

- 沈黙や未返信を同意として扱わない
- 非参加や低頻度参加を理由に、発言権や基本アクセスを下げない
- 個人別の貢献台帳、継続的な可視化ダッシュボード、謝意の集計表を作らない
- 全体ルールの変更は、当月アクティブ参加者の明示同意がある場合だけ適用する
- 発言しづらい懸念は、定例以外に非公開でも出せる
- 退出時の後処理は共同体側の責任で進め、本人の協力を前提条件にしない

## このフォルダにある文書

- `charter.md`: 目的、原則、禁止事項
- `governance.md`: 役割、提案方法、意思決定、退出ルール
- `experiments.md`: 最初の3か月で行う実験案
- `themes.md`: 最初に扱うテーマ候補

## 最小Webアプリ

このフォルダの実験をローカルで触れる最小Webアプリを追加しています。

- 画面URL: `http://localhost:3000/dao-participation-lab`
- 機能: 実験提案の一覧表示、新規提案、コメント、状態変更
- 状態: `draft / active / review / closed`
- 認証: なし

### 起動方法

```bash
npm install
npm run dev
```

起動後、ブラウザで `http://localhost:3000/dao-participation-lab` を開きます。

### ローカル保存

- 初期データ: `dao-participation-lab/data/seed-proposals.json`
- 実行時データ: `.tmp/dao-participation-lab/proposals.json`

初回アクセス時に、実行時データがなければシードから自動生成されます。状態をリセットしたい場合は `.tmp/dao-participation-lab/proposals.json` を削除してください。

## この設計書が扱わないもの

次の項目は、初期実験の範囲外です。

- 法人格の設立
- 利益分配や報酬制度の詳細設計
- 大規模コミュニティへの拡張
- トークン経済や投票アプリの導入
- 常設の評価制度

まずは少人数で始め、運営コストと心理的負担が低いかを確かめることを優先します。
