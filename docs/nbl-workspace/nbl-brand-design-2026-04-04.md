# NBL ブランド設計

作成日: 2026-04-04
前提ポジション: 「日本のデータが示す、インクルーシブ就労支援の実践知識。」
プライマリオーディエンス: 就労支援実践者（Q2→Q1転換を目指す支援者）

---

## ブランド構造の推奨

### 会社・組織名：Next Being Lab（NBL）を維持

**理由:**
- 「Lab」は正確。ここは知識が開発・蓄積される場所
- 研究者的な知的権威のシグナルとして機能する
- 変更コストに見合う理由がない

**ただし注意:** サイトで「Next Being Labとは何か」を説明しなくていい。会社名は背景にあり、知識の中身と実績が前面に出る。

### プロダクト名：レイヤー別に固有名を持つ

会社名（NBL）とは別に、各プロダクトに固有名を与える。使う人は会社名ではなく「使っているツール・コンテンツの名前」で覚える。

| プロダクト | 推奨名 | 説明 |
|---|---|---|
| AI対話相談UI | **はたらく相談室** | 個別の就労困難を対話で整理するAIツール。当事者・支援者どちらにも開かれた「場所」として機能する |
| 27フレームガイドブック | **仕事設計ガイドブック**（維持） | 典型状況のリファレンス。現行名が内容を正確に示している |
| 知識プラットフォーム全体 | **NBL**（会社名と統一） | サイト全体・知識ネットワーク全体の呼称はNBLのまま |

*「はたらく相談室」の技術実装メモ: 内部コード・環境変数は「JAC」のまま維持（`JAC_PUBLIC_ENABLED`等）。表示名のみ変更。URLは`/jac`（既存）または`/consult`（新規）どちらでも可。`/jac`維持が実装コスト最小。*

## タグライン

### 確定推奨

**「就労の詰まりを、設計の課題として解く。」**

**解説:**
- 「就労の詰まり」= 実践者が現場で感じる状態をそのまま言語化。共感の入口
- 「設計の課題として解く」= NBLの哲学的転換点を一言で示す（個人の問題→設計の問題）
- 読んだ瞬間に「自分のことだ」と思える実践者が多い
- 短く・断言している（研究者が書くと長くなりがちな文章への対抗）

### サブタグライン（場面別）

サイトの文脈によって使い分ける補助的なフレーズ。

| 場面 | フレーズ |
|---|---|
| 支援者向けページ | 「Q1支援者の実践知識を、誰でも使えるかたちに。」 |
| 企業・組織向けページ | 「多様な機能プロフィールを前提とした、仕事設計の知識。」 |
| 当事者向けページ | 「困難は、あなた個人の問題ではない。仕事と環境の設計の問題として解ける。」 |
| About・理念ページ | 「日本のデータが、インクルーシブ就労支援の実践を変える。」 |

## トーン定義

### 基本トーン：「実践的権威」

権威があるが、使う人に寄り添う。確信を持って書くが、説教しない。

| 要素 | 方向 |
|---|---|
| 確信の度合い | 断言する。「〜と考えられる」「〜かもしれない」は使わない |
| 感情の温度 | 温かいが感傷的でない。問題は直視する |
| 専門性の見せ方 | 根拠は示すが前面に出さない。「データが示すように」は使うが「n=3,053のGLM分析では」は本文から外す |
| 長さ | 短く。一文で言えることを二文で書かない |
| 主語 | できるだけ「あなた」「支援者」「当事者」。NBLを主語にしない |

### 避けるべき表現

*研究者バイアスが出やすいパターン:*

| 避けるべき | 理由 | 代わりに |
|---|---|---|
| 「本研究では〜」「本稿では〜」 | 学術論文の文体。サイトでは不要 | 直接主張する |
| 「〜という可能性がある」 | 過剰な留保。断言できることは断言 | 「〜です」 |
| 「限界と課題」 | 論文の必須セクション。サイトでは不要 | 言わない（知識の更新ループで対応） |
| 「FCHMAアトラスに基づく8ドメイン×6モチーフ」 | 方法論の前面化。使う人には不要 | 「日本のデータから導いた」で足りる |
| 「支援の必要性を感じる方はぜひ」 | 行政文書のような受動的な表現 | 「〜に使ってください」と能動的に |

### 参照トーンの例（仕事設計ガイドブックv3から）

既に良いトーンが確立している。以下のスタイルをサイト全体で統一する。

> 「働きづらさを診断名や個人特性で扱うのではなく、仕事・環境・支援・制度の設計課題として読み替えること」
> 「最終判断は支援者と本人が持ちます」
> 「最初にやること」「見落としやすい点」

→ **直接的・行動志向・本人起点** のスタイルをサイト全体に適用する。

## ホームページのキーメッセージ設計

### ファーストビュー（最初の3秒で伝えること）

**訪問者の頭に残すべき一文:**

> 「就労の詰まりは、仕事と環境の設計で解ける。」

**直下のサブテキスト（2〜3行）:**

> 日本の当事者・支援者のデータから導いた、インクルーシブ就労支援の実践知識。
> 27のフレームと対話AIが、現場の一手を示します。

### セカンドビュー（誰が使うか・何ができるか）

ロール別の分岐を「誰向け」という区画ではなく、「何を知りたいか」の問いで設計する。

```
今の相談事例を整理したい    → JAC（AI対話）
典型的な困難パターンを知りたい → 仕事設計ガイドブック（27フレーム）
支援実践の全体像を把握したい  → 知識ネットワーク（支援者向け）
職場・組織の環境設計を変えたい → 組織設計の知識
```

### キラーコンテンツとして機能するもの（公開直後から置くべき）

1. **「北海道33%、香川5.3%」の地域格差可視化**
   → 数字の力で問題の実在を示す。シェアされやすい

2. **「71.9%の支援者が意欲はあるが実施できない」という事実**
   → 支援者の自分事として刺さる。「私のことだ」という認知を作る

3. **仕事設計ガイドブックv3の無料公開**
   → 「これだけの知識が無料で使える」という信頼の構築

## ビジュアル方向性（デザイナーへの指示書として）

### 方向性のキーワード

「構造的・清潔・知的・温かい」

商業的な求人サイト（明るく活気的）でも、行政・医療サイト（硬い・冷たい）でもない。
研究と実践の中間にある知識の場所として見える。

### 具体的な指示

| 要素 | 方向 |
|---|---|
| 色 | 彩度を抑えた知的な配色。アクセントカラー1色のみ。明るすぎない |
| フォント | 読みやすさ優先。見出しに個性、本文は中性的 |
| 画像 | 人物写真は使わないか最小限（障害者のイメージ写真は絶対に使わない） |
| 構造 | フレームの「設計層」構造を視覚的に活かす。階層感・整理感を出す |
| アニメーション | ほぼ使わない。知識の内容で勝負する |

*研究者バイアス警告: 「ビジュアルより中身が大事」という考えは正しいが、ビジュアルが悪いと中身が読まれない。最低限の投資が必要。*
