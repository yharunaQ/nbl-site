# 就労支援実務者に必要な知識・スキル等の内容（5核改訂版）v0


## 5 Core

JEEDの16分類・65項目の障害者就労支援の基礎知識・スキルを次の5つの核へ再配置する。

1. `構造的に読む`: 困難を本人・仕事・環境・支援・時間・制度の相互作用として読む。
2. `本人と共同で証拠地図を作る`: 本人の希望、強み、健康、生活、職務、職場、制度を、視点ごとに分けて集める。
3. `介入を接点変更として設計する`: 支援策をメニューではなく、どの相互作用を変える仮説かとして設計する。
4. `実装条件を整える`: 企業、職場、家族、関係機関、制度、地域資源の役割と負荷を設計する。
5. `結果から学び直す`: 実施結果、未改善、副作用、例外、支援疲労から見立てと知識を更新する。

この5核は、実務者が何を見落としやすいかを明確にするための再配列である。

## Core 1. 構造的に読む

### statement

障害者就労支援の出発点は、障害名・能力・態度・意欲ではなく、本人・仕事・環境・支援・時間・制度の相互作用を読むことである。  
ICFはこの相互作用を読む主座標であり、ICDや診断名は健康条件ラベルの正規化・索引に限定する。

### PDF inheritance

- No.1 障害についての基本的理解
- No.2 障害者の働く意義と権利擁護・共生社会実現
- No.3 支援者が持つべき心構えと倫理意識
- No.4 支援者が取るべき態度
- No.5 支援者自身の自己理解
- No.6 最新情報の収集と自己研鑽
- No.7 支援者自身の身体・精神的ケア
- No.13-17 相談・説明・記録・情報取扱い
- No.21 自己選択・自己決定の支援

### Revised knowledge items

1. `AX-01 相互作用としての障害理解`  
   困難を、心身機能、活動、参加、職務要求、環境、人的関係、制度、時間変化の相互作用として読む。

2. `AX-02 事実・解釈・提案の分離`  
   相談、記録、会議、企業説明では、観察事実、本人の語り、支援者の推論、支援提案を混ぜない。

3. `AX-03 source lens の分離`  
   本人、家族、事業主、管理者、同僚、医療、福祉、雇用支援、制度の視点差を平均化せず、どの視点から見た情報かを保持する。

4. `AX-04 本人主権と共同検討`  
   本人中心とは、本人の言葉をそのまま結論にすることでも、専門職が本人を誘導することでもない。本人が理解し、選び、後から見直せる条件を作ることである。

5. `AX-05 同意と情報共有の設計`  
   同意は書類手続きではなく、誰に、何を、何のために、どの範囲で共有するかを本人と検討する専門技術である。

6. `AX-06 支援者の自己監査`  
   支援者は、固定観念、過剰な善意、企業寄り・本人寄りの偏り、支援者自身の限界を点検する。

7. `AX-07 現場知の更新姿勢`  
   研修参加や情報収集は、知識量を増やすだけでなく、現場の見立てを修正するために行う。

### 特に注意すべき考え違い

- `考え違い1: 障害名が分かれば支援が分かる`  
  Axiomでは、障害名は入口情報でしかない。支援は、職務、環境、時間、支援資源、本人の希望と強みの接点を見ないと決まらない。

- `考え違い2: ICFは分類コードを付ける作業である`  
  ICFの価値はコード付けではなく、活動・参加・環境・健康状態の相互作用を見えるようにすることにある。

- `考え違い3: 本人中心とは本人の希望をそのまま採用すること`  
  本人中心とは、希望と現実条件を一緒に構造化し、選択肢と結果を理解できるようにすること。

- `考え違い4: 記録は報告用の文章である`  
  Axiomでは、記録は後から見立てを検証するための証拠保存である。

- `考え違い5: 支援者のセルフケアは個人的な努力である`  
  支援者の疲弊や孤立は、ケース判断や倫理判断を歪める実装リスクである。

## Core 2. 本人と共同で証拠地図を作る

### statement

アセスメントは、本人の能力評価ではない。  
本人の希望・強み・困りごと、健康状態、生活条件、職務要求、職場環境、支援資源、制度条件を、本人と一緒に地図化する作業である。

### PDF inheritance

- No.18-21 自己理解・自己選択・自己決定
- No.22-30 就労支援における障害者のアセスメント
- No.36-38 仕事選択・求人・職場情報収集
- No.49-52 体調管理・生活・ライフステージ
- No.53-54 企業の実態・ニーズ把握

### Revised knowledge items

1. `AX-08 希望・強み・困難の同時把握`  
   希望だけ、困難だけ、強みだけを切り出さず、どの職務・環境なら力が出るかを一緒に見る。

2. `AX-09 生活・健康時間の把握`  
   通院、服薬、睡眠、疲労、回復時間、通勤、家族役割、経済不安は、職業能力の外側ではなく就労条件そのものである。

3. `AX-10 職務要求と評価基準の把握`  
   仕事内容、正確性、スピード、対人要求、予定変更、暗黙ルール、評価のされ方を具体的に把握する。

4. `AX-11 職場環境・人的関係の把握`  
   物理環境だけでなく、指示系統、相談しやすさ、キーパーソン、同僚の負荷、管理者の理解を確認する。

5. `AX-12 行動観察と体験の活用`  
   職場見学、実習、模擬場面、実際の勤務場面を、本人を試す場ではなく、接点の良し悪しを観察する場として使う。

6. `AX-13 複数視点の照合`  
   本人評価、支援者評価、職場評価、家族評価、医療情報をすり合わせる。ただし、不一致は消さずに保持する。

7. `AX-14 医学・心理学情報の位置づけ`  
   医学・心理学情報は、本人の状態理解とリスク把握に使う。支援策を診断名から自動決定するためには使わない。

8. `AX-15 企業側証拠の収集`  
   企業の求人票だけでなく、現場の業務構造、困りごと、受け入れ体制、評価軸、調整余地を把握する。

### 特に注意すべき考え違い

- `考え違い1: アセスメントは本人の能力を測ること`  
  Axiomでは、能力は職務・環境・支援条件によって現れ方が変わる。能力だけを測っても支援設計には足りない。

- `考え違い2: 強みに注目すればよい支援になる`  
  強みは、発揮条件とセットで見ないとスローガンになる。

- `考え違い3: 医療情報が客観的で、本人の語りは主観的で弱い`  
  医療情報、本人の語り、行動観察、職場情報は役割が違う。どれか一つを上位に置いて他を消してはいけない。

- `考え違い4: 職場情報は求人票と仕事内容で足りる`  
  実際には、暗黙ルール、相談経路、評価基準、変更頻度、同僚の支援可能性が重要になる。

- `考え違い5: 就労意欲が低いから難しい`  
  意欲は、失敗経験、健康不安、経済不安、支援不信、職務要求の見えなさから形成される場合がある。

## Core 3. 介入を接点変更として設計する

### statement

支援は、本人に何かを教えること、制度を紹介すること、企業に配慮を頼むことの集合ではない。  
支援とは、困難を生んでいる接点を変える介入仮説である。

### PDF inheritance

- No.30-35 計画、モニタリング、スキル習得、生活・通勤支援
- No.36-41 仕事選択、開示・非開示、求職活動、職場見学・実習
- No.42-48 合理的配慮、職場適応、ナチュラルサポート、フォローアップ、復職、退職・再就職
- No.49-52 体調管理、生活設計、ライフステージ対応
- No.55-58 企業説明、職場・職務調整、職務再構成、課題分析

### Revised knowledge items

1. `AX-16 介入仮説としての支援計画`  
   支援計画には、何を変えたいのか、誰が実行するのか、何を観察するのか、いつ見直すのかを書く。

2. `AX-17 本人側スキル支援の再配置`  
   スキル習得、SST、問題解決支援、通勤支援は、本人を直すためではなく、環境・職務・支援との接点を増やすために行う。

3. `AX-18 開示・非開示の意思決定支援`  
   開示は善、非開示はリスク、ではない。目的、共有範囲、得られる調整、失われる可能性、代替手段を検討する。

4. `AX-19 合理的配慮の合意形成`  
   合理的配慮は配慮メニューではなく、本人と事業主が職務・環境・支援条件を調整するプロセスである。

5. `AX-20 職務・環境調整`  
   手順化、道具、IT/ICT、作業場所、休憩、指示方法、評価基準、役割範囲を調整対象として扱う。

6. `AX-21 職務再構成・職務創出`  
   既存求人に本人を合わせるだけでなく、職務分析によって、できる仕事の組み合わせや新しい役割を作る。

7. `AX-22 職場内支援の形成`  
   ナチュラルサポートは自然発生に任せない。キーパーソン、支援範囲、相談経路、同僚・上司の負担を設計する。

8. `AX-23 移行と変化への介入`  
   就職、実習、復職、退職、再就職、配置転換、ライフステージ変化を、支援が必要な移行局面として扱う。

9. `AX-24 体調・生活・仕事の統合支援`  
   体調管理や生活設計は、仕事の外側の自己管理ではなく、仕事を続ける条件設計である。

### 特に注意すべき考え違い

- `考え違い1: 支援とは本人にスキルを身につけさせること`  
  スキル支援だけでは、職場の暗黙ルールや過剰な職務要求は変わらない。

- `考え違い2: 合理的配慮とは配慮例を選ぶこと`  
  Axiomでは、配慮例は素材であり、本体は職務・環境・本人状態・事業主条件をつなぐ合意形成である。

- `考え違い3: 職場適応とは本人が職場文化に合わせること`  
  Axiomでは、本人の行動変化と職場側の明示化・調整を同時に見る。

- `考え違い4: ナチュラルサポートは職場に任せればよい`  
  任せるだけでは、同僚・上司の善意に依存して破綻する。支援範囲、相談経路、支援者のフェードアウト条件が必要。

- `考え違い5: マッチングとは本人に合う求人を探すこと`  
  Axiomでは、求人探索だけでなく、職務再構成、職務創出、要求水準の調整もマッチングである。

## Core 4. 実装条件を整える

### statement

よい見立てや支援案があっても、実装主体、制度条件、企業運用、地域資源、家族関係が整わなければ支援は動かない。  
Axiomでは、誰が何を実行できるか、誰に負荷がかかるか、どこで合意が必要かを専門知識の一部として扱う。

### PDF inheritance

- No.8-12 法令・制度・サービス、企業経営、労働法、雇用管理
- No.42-46 職場内の話し合い、職場適応、ナチュラルサポート、フォローアップ
- No.53-58 企業アセスメントと支援
- No.59-63 地域資源、関係機関連携、ケース会議、家族連携
- No.64-65 啓発、支援人材育成

### Revised knowledge items

1. `AX-25 制度条件の把握`  
   法令、合理的配慮、福祉サービス、所得保障、労働法、社会保険は、ケースの背景条件として把握する。

2. `AX-26 企業運用の把握`  
   採用、配置、評価、教育、労務、安全衛生、現場管理の流れを理解し、支援案がどこに入るかを見る。

3. `AX-27 企業ニーズと権利保障の両立`  
   企業の困りごとやメリットを扱うが、権利保障や本人の参加条件を企業利益へ回収しない。

4. `AX-28 役割分担の明示`  
   本人、支援者、事業主、上司、同僚、家族、医療、福祉、雇用支援機関が何を担うかを明示する。

5. `AX-29 ケース会議の構造化`  
   ケース会議は情報共有の場ではなく、証拠、見立て、介入、リスク、役割分担、次回確認を揃える場である。

6. `AX-30 家族等との連携`  
   家族は本人の代弁者でも管理者でもない。本人同意のもとで、生活条件や支援資源の一部として位置づける。

7. `AX-31 地域資源ネットワーク`  
   地域資源は紹介先リストではなく、個別ケースで機能する支援条件の組み合わせとして把握する。

8. `AX-32 啓発・人材育成`  
   啓発や研修は、よい話を広めることではなく、誤った見立てと実装失敗を減らすために設計する。

### 特に注意すべき考え違い

- `考え違い1: 法制度を知っていれば正しい判断ができる`  
  法制度は重要な背景条件だが、個別ケースの最終判断や法的助言そのものではない。公開利用前には最新確認が必要。

- `考え違い2: 企業メリットを示せば雇用は進む`  
  メリット説明だけでは、職務設計、現場負荷、評価基準、相談経路は変わらない。

- `考え違い3: 連携とは紹介すること`  
  紹介だけでは支援はつながらない。何を引き継ぎ、誰が次に何を見るかまで設計する。

- `考え違い4: ケース会議は関係者が集まればよい`  
  情報が混ざるだけの会議は、むしろ責任と見立てを曖昧にする。

- `考え違い5: 啓発は理解を広めること`  
  Axiomでは、啓発は「診断名短絡」「本人努力主義」「企業都合回収」などの誤解を減らす設計である。

## Core 5. 結果から学び直す

### statement

支援は、計画を作った時点でも、就職した時点でも終わらない。  
実施結果、未改善、逆効果、例外、支援疲労、制度上の限界を記録し、見立て・介入・知識を更新するところまでが専門性である。

### PDF inheritance

- No.6 自己研鑽と最新情報
- No.16 記録・伝達
- No.31 計画策定とモニタリング
- No.41 職場実習の振り返り
- No.46 フォローアップ
- No.47-48 復職、退職、再就職
- No.49-52 体調・生活・ライフステージ
- No.58 課題分析と解決策
- No.65 支援人材育成

### Revised knowledge items

1. `AX-33 アウトカムの多元化`  
   結果は就職・定着だけではない。役割適合、健康時間、相談可能性、支援負荷、生活安定、再発予兆、本人の納得も見る。

2. `AX-34 介入後レビュー`  
   支援実施後に、何が変わったか、何が変わらなかったか、何が悪化したかを確認する。

3. `AX-35 見立ての更新`  
   結果を見て、もとの構造仮説を維持するのか、修正するのか、別仮説を立てるのかを判断する。

4. `AX-36 例外と失敗条件の保存`  
   うまくいかなかった支援、効かなかった条件、逆効果、本人や職場の負荷を、失敗ではなく知識として保存する。

5. `AX-37 支援者・職場側の負荷レビュー`  
   支援者、上司、同僚、家族、関係機関に無理が蓄積していないかを確認する。

6. `AX-38 知識成熟度の管理`  
   個別ケースの気づきは、すぐ普遍知識にしない。複数ケース、例外、アウトカム、人間レビューを経て初めて再利用候補になる。

7. `AX-39 AI時代の監査`  
   AI出力は候補であり、最終判断ではない。モデル出力、prompt version、人間修正差分、レビュー状態を分けて残す。

### 特に注意すべき考え違い

- `考え違い1: 就職できたら支援成功`  
  就職後に健康、役割、評価、相談可能性、生活が崩れているなら、成功とは言えない。

- `考え違い2: フォローアップは様子確認`  
  Axiomでは、フォローアップは構造仮説と介入仮説を検証するレビューである。

- `考え違い3: 成功事例はそのままノウハウになる`  
  成功事例は、条件、例外、失敗可能性が分かって初めて再利用できる。

- `考え違い4: 研修を受ければ専門性が上がる`  
  専門性は、現場結果から見立てを修正できることで上がる。

- `考え違い5: AIが整理したら知識になる`  
  AI整理は候補生成であり、証拠、レビュー、実装結果、人間修正がなければAxiom知識にはならない。

## 語彙の寄せ方

| PDFでの言い方 | 推奨語彙 | 理由 |
| --- | --- | --- |
| 障害特性 | 健康条件・機能特性・条件窓 | 診断名短絡を避け、職務・環境との相互作用へ接続する |
| 利用者中心 | 本人主権と共同検討 | 本人任せでも専門職主導でもないことを明確にする |
| アセスメント | 証拠地図づくり / 相互作用構造化 | 能力評価に狭まるのを防ぐ |
| 見立て | 構造仮説 | 反証・修正可能な候補であることを明確にする |
| 支援計画 | 介入仮説と実装計画 | 何を変える支援かを示す |
| 合理的配慮 | 職務・環境・支援条件の合意形成 | 配慮メニュー化を防ぐ |
| 職場適応 | 職場接点デザイン | 本人同化への誤読を避ける |
| 連携 | 実装主体・役割分担の設計 | 紹介や情報共有に狭めない |
| フォローアップ | アウトカムレビュー / 見立て更新 | 様子確認に終わらせない |
| 研修・自己研鑽 | 知識更新ループ | 受講実績ではなく専門知の更新として扱う |

## Revised List Summary

改訂版として普及する場合、見出しは次のように置く。

1. `相互作用として読む専門性`
   - 障害名ではなく条件の組み合わせを見る。
   - 観察、本人の語り、推論、提案を分ける。
   - ICFを構造理解の座標として使う。

2. `本人と共同で作る証拠地図`
   - 希望、強み、困難、健康、生活、職務、職場、制度を同時に見る。
   - 複数視点の不一致を消さずに扱う。
   - 医学情報を支援策へ直結しない。

3. `接点を変える介入設計`
   - 支援策をメニューではなく介入仮説にする。
   - 本人側支援と職場側設計を対にする。
   - 合理的配慮を合意形成として扱う。

4. `実装条件の設計`
   - 企業、制度、家族、関係機関、地域資源の役割と負荷を見る。
   - 連携を紹介ではなく役割分担として設計する。
   - 啓発を誤解修正として設計する。

5. `結果から学び直す専門性`
   - 就職・定着だけでなく、健康、役割、相談可能性、支援負荷を見る。
   - 未改善、副作用、例外を保存する。
   - AI出力や単一成功事例をすぐ知識化しない。
