# FCHMA Causal Framework Atlas

## Positioning

FCHMA の方法論的な核は、

- 個別相談をそのまま病名辞書で捌くことではなく
- manifold 上に反復して現れる因果関係の型を
- 理解可能な causal framework atlas として保持し
- そこから製品 view を切り出すこと

にある。

したがって、`3レイヤー・26フレーム` は重要だが、
それ自体を最上位の母集団として扱うべきではない。

## New Rule

今後の設計では、

1. `FCHMA causal framework atlas`
2. `data-derived manifold pattern library`
3. `product-facing views such as 3-layer / 26-frame cuts`

の順で上下関係を持たせる。

## Atlas Design

初版 atlas は `48` フレームで構成する。

- `8 domains`
- `6 motifs`
- `8 x 6 = 48 frameworks`

### Domains

1. 症状変動
2. 仕事要求ミスマッチ
3. 参加・役割不安定化
4. 配慮・環境ギャップ
5. 説明・開示媒介
6. 支援連携アクセス
7. 時間経過・移行不安定化
8. 制度制約・制度アクセス

### Motifs

1. 増幅
2. ミスマッチ
3. ボトルネック
4. 緩衝
5. 補償
6. 遅延・再燃

## Why This Is Better Than Starting From 26

- `26` は説明 view としては強い
- しかし母集団としては粗く、切り分け前に圧縮しすぎる
- FCHMA の本質は、先により広い causal atlas を持ち、その後に切ること

つまり、

- `atlas` が canonical methodological core
- `26 frames` は one product projection

である。

## Relationship To Current Manifold Patterns

respondent-side manifold pattern extraction はすでに始まっているが、
現状のパターン数はまだ `15` にとどまり、しかも

- fatigue / schedule
- communication barrier
- accommodation gap

に寄っている。

これは atlas の一部 occupancy であって、atlas 全体ではない。

## Intended Use

次期 JAC では、

- minimal consultation
- pattern prior matching
- causal hypothesis generation

の間に、

- atlas domain
- atlas motif
- atlas layer

を明示的に通す。

これにより、

- まず最大の網羅性を確保し
- その後で問題を view ごとに切り分ける

という順序を守れる。
