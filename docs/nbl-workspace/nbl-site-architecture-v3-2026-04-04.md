# NBLサイト アーキテクチャ v3

作成日: 2026-04-04
前版: nbl-site-architecture-v2-2026-04-03.md（本文書で更新・統合）
前提ポジション: 「日本のデータが示す、インクルーシブ就労支援の実践知識。」
プライマリオーディエンス: 就労支援実践者（Q2支援者）
公開方針: Phase 1・Phase 2 を一括公開

---

## ナビゲーション設計の原則

「誰ですか」ではなく「何をしたいですか」を軸にする。
ユーザータイプ別の区画（当事者向け・支援者向け）は作らない。
どの入口から来ても、同じ知識ネットワークにたどり着く。

---

## トップナビゲーション（5項目）

```
相談する  |  フレームを使う  |  実践知識を学ぶ  |  職場・組織を変える  |  NBLについて
```

各項目の命名がユーザータイプでなく**行動**であることに注意。
「支援者向け」「当事者向け」という区画はない。

---

## 各セクションの設計

---

### `/` ホーム

**役割**: 3秒で「ここで何ができるか」を伝え、最適な次の行動へ誘導する

**ファーストビュー（画面内に収まる範囲）:**

```
[タグライン]
就労の詰まりは、仕事と環境の設計で解ける。

[サブテキスト]
日本の当事者・支援者のデータから導いた、インクルーシブ就労支援の実践知識。
27のフレームと対話AIが、現場の一手を示します。

[行動ボタン 2つ]
今の事例を相談する →    フレームを調べる →
```

**セカンドブロック（スクロール後）: 問題の実在を示す数字**

```
71.9%  の就労支援者が、意欲はあるが実施できていない
6倍    都道府県によって就労支援の実践率に最大6倍の差がある
9,000件超  当事者・支援者の実データから導いた知識
```

*設計注意: 「71.9%の支援者」と「6倍の格差」は支援者コミュニティへの問題提起として機能する。地域名は出さない。*

**サードブロック: 4つの入口**

```
今の相談事例を整理したい   → JAC（AI対話）
典型的な困難を調べたい     → 仕事設計ガイドブック
支援実践の全体像を知りたい  → 実践知識
職場・組織の環境を変えたい  → 職場・組織設計
```

---

### `/jac` JAC — AIによる個別相談

**役割**: 個別の就労困難を対話で構造化し、具体的な一手を示すAIツール

**現状**: FCHMAベースのAI相談UI（`/jac/next`）実装済み。完成版知識ネットワーク対応に更新して公開。

**ページ構成:**

| パス | 内容 |
|---|---|
| `/jac` | JACの説明・使い方・入口 |
| `/jac/next` | AI対話UI本体 |

**JACランディングページ（`/jac`）に置くもの:**
- 「JACとは何か」を3行で（診断ツールではなく相談ツール。最終判断は支援者と本人が持つ）
- 使い方の例（「どんな状況を入力すればよいか」）
- プライバシーについての説明（入力内容の扱い）

**トーン注意:**「AIが診断します」という表現は使わない。「AIが一緒に整理します」。

---

### `/guide` 仕事設計ガイドブック

**役割**: 27の典型的な就労困難パターンを整理したリファレンス。当事者・支援者どちらにも機能する。

**ページ構成:**

| パス | 内容 |
|---|---|
| `/guide` | ガイドブックの説明・3設計層の地図・全27フレーム一覧 |
| `/guide/[frame-id]` | 各フレームの個別詳細ページ |
| `/guide/download` | PDF・印刷用版のダウンロード |

**`/guide` トップページのデザイン:**

```
[タイトル]
仕事設計ガイドブック

[説明 2行]
就労の困難を「個人の問題」ではなく「設計の課題」として読み替える27のフレーム。
当事者が自分の状況を整理するためにも、支援者が現場で使うためにも設計されています。

[3設計層のビジュアル地図]
設計層Ⅰ 症状・経過との共存設計（7フレーム）
設計層Ⅱ 仕事・環境の適合設計（11フレーム）
設計層Ⅲ 参加経路と社会的接続の設計（9フレーム）

[全フレーム一覧（カード形式）]
```

**各フレームページ（`/guide/[frame-id]`）:**
- 核心問題一文
- 状況レベル（🟢→💣）
- 鑑別診断
- 具体的な取組み内容
- 「外部と一緒に考える場面」（Q13・supports.mdデータ付き）
- 関連フレームへのリンク

### `/knowledge` 実践知識・エビデンス

**役割**: 個別事例を超えた、構造的・社会的な知識を提供するセクション。「日本のデータが示す」という根拠を示す場所。

#### `/knowledge/practice` Q1支援者の実践知識

**内容:**

**目的:** Q2支援者が「自分にもできる」と感じられる実践知識の提供

| コンテンツ | 内容 | 根拠データ |
|---|---|---|
| Q1とQ2の実践の違い | 何が違うのか、具体的な対比 | toku18 narrative分析 |
| Q2→Q1転換の3つの入口 | 実践経験・機関研修・ピア交流 | Q12データ（+0.199等） |
| 効果的な連携体制の選び方 | どの機関とつながると変わるか | Q13データ（+17.0pt等） |
| 「参加の質」の設計 | 参加率より参加の質が重要な理由 | 地域別転換効率データ |

**形式:** 各トピック1〜2ページの読み物（記事）形式。図表を含む。

#### `/knowledge/evidence` データ・地域格差・調査結果

**内容:**

**目的:** 問題の構造を可視化する。政策立案者・研究者・ジャーナリストが引用できる素材を提供。

| コンテンツ | 内容 | 実装 |
|---|---|---|
| 地域格差可視化 | 都道府県別Q1率の分布（最大6倍） | インタラクティブマップまたは図 |
| 71.9%問題の解説 | Q2支援者が実施できない理由の構造 | 記事 + 図 |
| 知識ネットワークの説明 | FCHMAアトラス・データ基盤の概要 | 技術解説ページ |
| IPS/SE日本独立整合 | 日本データがIPS/SE原則を独立再発見した事実 | 記事 |

**地域格差可視化の設計注意:**
- 都道府県の分布は示す（全体像としての格差）
- 「最悪の県」「最良の県」という表現は使わない
- 「あなたの地域はどこか」という入力は任意
- 目的は「格差の実在と構造」の理解であり、地域の批判ではない

#### `/knowledge/network` 地域連携体制ナビ

**内容:**

**目的:** Q13データに基づく「どの機関とつながればQ1転換につながるか」のガイド

| コンテンツ | 内容 |
|---|---|
| Q1転換効果の機関ランキング | 就労移行支援+17.0pt、就業生活支援センター+16.4pt等 |
| 機関別の特徴と活用法 | 各機関が何を得意とするか |
| 「参加しているが転換しない」問題 | 参加の質を上げるための設計 |

### `/organizations` 職場・組織設計の知識

**役割:** 個人・事例レベルを超えた、組織・職場環境の設計課題に対応するセクション。

**プライマリ読者:** 就労支援機関の管理職・機関長 + 企業のHR・産業医

#### `/organizations/design` インクルーシブ職場設計

**内容:**

| コンテンツ | 内容 | 根拠 |
|---|---|---|
| 27フレームの組織設計版読み方 | 支援者個人の問題でなく組織設計の問題として読む | FCHMAアトラス |
| 機能的多様性を前提とした仕事設計 | 27フレームの知識を職場設計に転用 | 仕事設計ガイドブック |
| IPS/SE原則の日本版実践ガイド | 日本データから導いた「今から始められる」設計 | 日本データ+IPS/SE整合 |

#### `/organizations/diagnosis` 組織診断

**内容:**

「なぜ支援者が動けない組織になっているか」を診断する簡易ツール。

診断軸（Q14データ由来）:
1. 上司・職場文化（最大規定因子: Q1-Q2差+0.131）
2. 機関ミッション・法令理解（+0.118）
3. 業績評価基準（+0.117）
4. 資金・報酬基準（+0.110）
5. 専門職規範（+0.101）

結果として「あなたの組織はどのタイプか」と「何から変えるか」を示す。

### `/about` NBLについて

**役割:** NBLの設計思想・データ基盤・開発方針を説明する。信頼性の根拠を示す場所。

| パス | 内容 |
|---|---|
| `/about` | NBLとは何か・なぜ作ったか・設計思想 |
| `/about/knowledge-base` | 専門知識ネットワークの説明（FCHMAアトラス・3ループ） |
| `/about/data` | データ基盤の概要（調査規模・方法・倫理） |

**`/about`トップページの核心メッセージ:**

> 「NBLは、日本の当事者と支援者のデータから、インクルーシブ就労支援の実践知識を開発・提供する知識プラットフォームです。」

**データ説明での研究者バイアス警告:**
- 調査の詳細（GLM・FCHMA・クラスタリング）は`/about/data`に置き、トップには出さない
- 「n=9,076」は信頼性の根拠として使うが、方法論の詳細は興味ある人向けに置く
