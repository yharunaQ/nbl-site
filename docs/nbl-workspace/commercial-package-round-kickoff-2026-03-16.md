# Commercial Package Round Kickoff

更新日: 2026-03-16

## この文書の役割

この文書は、`first commercial package を employer 用と intermediary 用で分けるか` を、Codex のマルチエージェント運用で回すための kickoff pack。

## Round Question

- 最初の commercial package は:
  - `1つの core package + 2つの wrapper` にするか
  - `employer 用と intermediary 用の別 product` に分けるか

補助問い:

- どちらが consulting drift を防ぎやすいか
- どちらが recurring layer を説明しやすいか
- どちらが partner edge と human review boundary を壊しにくいか

## ゴール

この round では、次の 5 つを決める。

1. smallest sellable package
2. included / excluded / conditional
3. employer wrapper の定義
4. intermediary wrapper の定義
5. words to avoid

## 使う agent

Round A:

- Offer Packaging Lead
- Revenue Architect

Round B:

- Safety and Boundary Lead

Round C:

- Validation Ops Lead

Round D:

- Chief of Staff

## Agent ごとの追加指示

### Offer Packaging Lead

- split product にすると何が壊れるか
- shared core にすると何が守れるか
- included / excluded / conditional をどう切るか

### Revenue Architect

- startup + recurring + bounded usage を package にどう埋め込むか
- employer / intermediary でどこだけ変えるべきか
- 価格より前に scope をどう固定するか

### Safety and Boundary Lead

- package wording が unsafe automation を誘発しないか
- exclusion line が薄くなっていないか
- diagnosis-only framing や final employment judgment への drift がないか

### Validation Ops Lead

- discovery call で package fit をどう確認するか
- confirm / falsify evidence は何か
- next 3-4 conversation で何を聞くか

### Chief of Staff

- one core / two wrappers が本当に最適か
- どこまで public に言ってよく、どこから internal only か
- 次の outreach material に何を渡すか

## 完了の定義

- smallest sellable package が 1 つに絞れている
- wrapper 差分が bounded になっている
- excluded items が明文化されている
- words to avoid が揃っている
- `/review/commercial-package-round` に落とせる
