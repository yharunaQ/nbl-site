# Partner Discovery Ops Round

更新日: 2026-03-16

## Scope

- 対象論点:
  - 次の 3-4 件の discovery conversation をどの相手条件で回すか
  - scorecard をどこで fixed にするか
  - outreach をどの順序と message で始めるか
  - falsification trigger をどこで明示するか

## Validation Ops Lead Memo

## What seems strongest

- discovery は `数打ち` より `条件を固定して比較する` 方が NBL に合う
- 最初の target condition は 3 つに絞るべき
  - employer-facing intermediary
  - design-forward employer
  - research / policy lighthouse
- 3 種の target を混ぜることで、commercial fit と legitimacy fit の両方が見える

### Fixed Target Conditions

#### Target A: Employer-facing intermediary

- employer network を持つ
- named operational owner がいる
- contextual review や external escalation に前向き
- repeated use が見込める
- public-good rhetoric だけで fee を薄めない

#### Target B: Design-forward employer

- workflow redesign appetite がある
- named internal sponsor がいる
- 1 本目の workflow lane を絞れる
- AI を人減らしでなく work redesign に使いたい
- boundary line を受け入れる

#### Target C: Research / policy lighthouse

- legitimacy と translation に資する
- field or network access がある
- immediate revenue は弱くても learning value が高い
- commercial package そのものより discovery intelligence に寄与する

## What seems risky

- target 条件を広げすぎると、相手選びが network convenience に引っ張られる
- scorecard を call のたびに変えると、比較ができなくなる
- lighthouse 相手を revenue lead と勘違いすると、commercial evidence が取れない

## What needs to be true

- target A を主軸にしつつ、B と C を比較対象として残す
- scorecard は 8 項目で固定する
- outreach の first objective は sell ではなく fit evaluation に置く

## Provisional recommendation

- outreach ratio は `A:2 / B:1 / C:1`
- scorecard は今回で fixed にする
- 4 conversation で provisional ranking を出す

## Safety and Boundary Lead Memo

## Holistic Positioning

- Scope of source:
  - design partner round、commercial package round、commercial discovery kit
- Covered lenses:
  - `difficulty_occurrence`
  - `difficulty_resolution`
  - `support_need_formation`
- Missing lenses:
  - actual partner review capacity
  - local legal / institutional pathway per target

## What is currently usable

- Usable now (with conditions):
  - target condition に `human review boundary acceptance` を入れること
  - scorecard に `low automation pressure` を残すこと
  - discovery call で required context の確認責任を先に聞くこと
- Not yet usable:
  - diagnosis-based narratives だけで fit を判断すること
  - target A を自動的に safest とみなすこと
  - lighthouse partner に operational review capacity を期待すること

## Bias/Discrimination Risk

- Risk level: medium
- Risk factors:
  - employer-facing intermediary が diagnosis-only framing を複数現場へ持ち込むと context collapse が起きる
  - employer が HR automation pressure を持つと employment action support へ drift する
  - lighthouse partner は legitimacy があっても case escalation owner になれないことがある

## Additional Information Required

- Must-have questions:
  - missing context を誰が埋めるか
  - must-escalate case を誰が引き受けるか
  - final employment judgment を package scope 外と理解しているか
- Nice-to-have questions:
  - de-identified learning を共有できるか
  - escalation turnaround expectation は何か

## Provisional recommendation

- target scorecard に次を固定する
  - boundary readiness
  - low automation pressure
  - operational context access
- outreach message に `not labor outsourcing` を一文入れる

## Chief of Staff Synthesis

## Agreed structure

- 次の discovery は `A:2 / B:1 / C:1`
- scorecard は 8 項目で fixed
- outreach は `brief -> exclusions -> boundary -> fit questions` の順

## Fixed Scorecard

1. repeated use potential
2. named internal owner
3. workflow redesign appetite
4. boundary readiness
5. operational context access
6. private workspace readiness
7. budget tolerance for startup + recurring
8. low automation pressure

## Outreach Sequence

1. short outreach note
2. if interest:
   - one-page package brief
3. before deepening:
   - exclusions list
   - boundary one-pager
4. during call:
   - discovery call guide
5. after call:
   - scorecard scoring

## Provisional decisions

- primary target condition:
  - employer-facing intermediary
- secondary target condition:
  - design-forward employer
- tertiary comparison target:
  - research / policy lighthouse

## Falsification Trigger

- 2 件連続で labor outsourcing expectation が強い
- 2 件連続で boundary line への同意が得られない
- 2 件連続で repeated use より one-off support しか想定できない

## Decision-ready note

- NBL の next step は、相手探しを広げることではなく、fixed target condition と fixed scorecard で 4 conversation を比較すること
- これにより `雰囲気のある相手` でなく `社会OSとして育つ相手` を見分けやすくする
