## 1. 何が本当に「実データから導出」されているか

### 1-A. データ実態（これは本物）

| 項目 | 実態 |
|---|---|
| 分析対象件数 | 9,076件（employment_survey_3000: 3,076件 + nanbyo_survey_4000: 6,000件） |
| クラスター数（グローバル） | 11（k-means） |
| 最終パターン数 | 44（global 11 + local 17 + micro 16） |
| 特徴量次元 | 78次元（数値特徴22 + スパーストークン240上位 + キーワードグループ8）→ SVDで12次元 |

これらは **実際のクラスタリング計算結果** であり、データから導出されている。

**パターンごとに実データに基づいて異なるもの:**

- `cluster_subject_count` — 各クラスターに実際に属した回答者数（例: 171件〜1,620件）
- `dominant_keyword_groups` — クラスター内で統計的に多いキーワードグループ（例: communication > cognition > support）
- `top_labels_by_concept` — health_condition・work_status・accommodation_and_supportの上位ラベル（実回答の集計）
- `representative_narratives` — 各クラスターから実際に抽出した代表自由記述
- `dataset_mix` — クラスター内のデータセット構成比（難病調査のみ / 障害者雇用のみ / 混在）

### 1-B. 実データに基づいて計算されているが、同質性のせいで分化しなかったもの

`causal_framework.summary` と `causal_framework.chain` は、各クラスターのラベル・キーワードから **ルールベースで動的に計算** されている（ハードコードのテンプレートではない）。

しかし、**43/44パターンで全く同一の結果** になっている：

```
health_condition -> activities / activities -> participation /
environmental_factors -> participation / personal_factors -> participation
```

原因: ほぼすべてのクラスターで以下の4条件が全て真になるため。

| 条件 | 判定ロジック | 真になりやすい理由 |
|---|---|---|
| activity_burden | fatigue/pain/cognition等のキーワード > 0 | 全調査で健康課題を持つ回答者 |
| environment_gap | support関連ラベルまたはsupportキーワード > 0 | 全クラスターにsupport言及あり |
| participation_strain | activity_burden OR work_status に不安定ラベル | 就労困難者が対象なので自明 |
| personal_fragility | emotion キーワード > 0 OR 将来不安ラベル | 不安記述は全クラスターに存在 |

**これはテンプレート問題ではなくデータの同質性問題。** 対象者が「就労困難を抱える人」に限定されているため、全員が4つの経路すべてを持つ構造になる。

`amplifiers` と `intervention_ports` も同じ理由で全43パターン同一。

## 2. クラスタリング手法の正確な説明

### 2-A. 実際に使われた手法

**SVD（特異値分解）+ k-means**

1. **特徴量構築**（78次元）
   - 構造化数値特徴: canonical_concept別カウント（18次元）+ primary_frame別（5次元） + response_type別（4次元）
   - スパーステキストトークン: 全自由記述からmin_df=最大(8, 件数×1.5%)、max_df=75%でフィルタした上位240トークン（TF-IDF類似）
   - キーワードグループ: 8グループのキーワード出現フラグ

2. **次元削減**: SVDで78次元 → 12次元（中心化後の主成分）

3. **クラスタリング**: k-means（ユークリッド距離、n_init=8〜10、最大反復60〜80回）
   - k の選択: ルールオブサム（件数 < 2,000 → k=7、< 5,000 → k=9、それ以上 → k=11）

4. **多段階分割**:
   - グローバル: 全9,076件でk=11
   - ローカル: 1,600件以上のクラスターをさらに最大4分割
   - マイクロ: 900件以上のサブクラスターをさらに最大3分割

### 2-B. 使われていない手法（名称と実態のギャップ）

| 用語 | 実態 |
|---|---|
| 「マニフォールド」 | SVD + k-meansは標準的な次元削減+クラスタリング。多様体学習（UMAP/t-SNE）は未実施 |
| 「マニフォールドパターン」 | クラスタリングで得られた統計的グループ。数学的な多様体の意味ではない |
| 「因果連鎖から導出」 | 因果連鎖はクラスタリング後にルールで付与。因果推論やグラフ学習は使っていない |

## 3. FCHMAの8ドメイン × 6モチーフ = 48フレームについて

**これはデータから帰納的に導出されたものではない。**

8ドメイン（D1〜D8）と6モチーフ（M1〜M6）は、ICF（国際生活機能分類）の概念構造と就労支援の専門知識を元に **演繹的に定義した分析語彙** である。

- アトラスはパターン分析の結果を「読む」ための枠組みであり、パターン分析の出力ではない
- 26フレームはアトラスからの「製品投影」（product projection）であり、さらに下流の概念

正確な階層:

```
専門知識・ICF（演繹）
        ↓
FCHMAアトラス（8D×6M=48フレーム）← ここは理論的枠組み
        ↓
クラスタリングで得たパターン（44）← ここが実データ由来
        ↓
26フレームへの投影（product projection）← アトラスを通した解釈
```

## 4. 人間の確認が必要な点（論文化前の必須作業）

### 4-A. クラスタリング品質の検証

現時点で未実施:

- **シルエット係数**: 各クラスターの凝集性・分離性の定量評価
- **エルボー法**: k=11の選択が統計的に妥当かの確認
- **クラスター安定性**: 異なるランダムシードで結果が安定するか
- **2つのデータセットの混在**: employment_survey_3000と nanbyo_survey_4000を合算することの妥当性（母集団が異なる可能性）

### 4-B. パターン内容の実質的検証

各パターンについて人間が確認すべきこと:

1. **`dominant_keyword_groups` の妥当性**
   例: `communication_barrier_pattern_1` は「support, communication, cognition, time_schedule」→ この組み合わせが本当にそのクラスターを特徴づけているか

2. **`top_labels_by_concept` の解釈**
   例: pattern_1のhealth_conditionに「ベーチェット病, 下垂体前葉機能低下症」→ 希少疾患クラスターとして意味があるか

3. **代表記述の代表性**
   現在の `representative_narratives` は機械的な抽出。各クラスターの「典型像」を最もよく表しているか

4. **因果構造の解釈**
   現在の `causal_framework` は全同一で無意味。本当の因果的差異は:
   - keyword_countsの比率（fatigueが強いクラスター vs communicationが強いクラスター）
   - top_labels_by_conceptの具体内容
   → これらを見て、各クラスターに **人間が命名・解釈を付与** する必要がある

5. **44パターンが多すぎないか**
   グローバル11クラスターで大半の説明ができる可能性がある。44への細分化が有意義かの確認

### 4-C. causal_frameworkの再設計

論文に書けるレベルにするには、現在の同一化したcausal_frameworkを以下のいずれかで差し替える必要がある:

**オプション1（推奨・工数中）**: キーワード比率プロファイルによる分類
- 各クラスターの{fatigue, pain, communication, cognition, mobility, emotion}の比率から因果経路の「重み」を計算
- 例: fatigue比率 > 0.5 → 「体力消耗型」、communication比率 > 0.4 → 「情報処理負荷型」

**オプション2（工数大）**: 専門家による44パターンの個別解釈
- representative_narrativesとtop_labels_by_conceptを人間が読んで、各クラスターに意味のある因果仮説を付与

**オプション3（工数小・現実的）**: causal_frameworkをAIシステムに使わせることをやめ、純粋に「類似クラスタ情報」として提示する
- 現在のUIはこの方向に修正済み（causal_summaryではなく実データを表示）

## 5. 論文として主張できること・できないこと

### 主張できること ✅

- 2つの就労困難者調査（計9,076件）を結合し、SVD+k-meansで多段階クラスタリングを実施した
- 44の統計的クラスターが得られ、各クラスターは健康状態・就労状況・支援ニーズの組み合わせで特徴づけられる
- クラスター間でdominant_keyword_groupsおよびtop_labels_by_conceptに有意な差異が見られる
- 代表自由記述はクラスターごとに異なる類型の困難を示唆している

### 慎重に扱うべきこと ⚠️

- 「マニフォールドパターン」の命名: 多様体学習は使っていない。「クラスタリングパターン」が正確
- k=11, k=44の選択: 統計的検証未実施。探索的分析として位置づけるべき
- 2データセットの結合: 母集団の異質性について議論が必要

### 主張すべきでないこと ❌

- 「FCHMAの因果連鎖から導出した44パターン」: 因果推論は使っていない
- 「実データから帰納的に得られた因果フレームワーク」: causal_frameworkはルールベース付与であり、同質的で無意味
- 「44パターンで就労困難の多様性を網羅」: クラスター品質の検証が未実施
