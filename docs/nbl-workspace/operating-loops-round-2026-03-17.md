# Operating Loops Round

更新日: 2026-03-17
Status: hidden review draft

## Why this round exists

NBL は `AI中心で事業を進める` 方向へかなり入っているが、Founder から見ると、まだ `進めて` という会話トリガーで動いているように見えやすい。

これは role が足りないというより、`日々どう回り続けるか` の loop が 1 枚で見えていないことが原因。

## Working conclusion

NBL の operating model は、少なくとも次の 5 loop に分けて見るとよい。

1. Chief of Staff Loop
2. Public Narrative Loop
3. Business Validation Loop
4. Knowledge And Method Loop
5. Next Horizon Loop

## Design principle

- 1 loop は `input -> comparison -> synthesis -> artifact` を持つ
- Founder は各 loop の実務には常駐せず、`外部行動 / public promise / 実名情報 / 不可逆判断` だけを決める
- どの loop も、単発会話で終わらず、decision log か reusable asset を残す

## Why this matters

- マルチエージェントらしさは、役職名より `繰り返し回る判断機構` にある
- Founder が律速段階になるのを避けるには、止まる条件を減らし、止まる条件を明示する必要がある
- NBL では、Horizon 1 の現実R&Dと Horizon 2 の芽出しが並走するため、単一 backlog では見通しが悪くなりやすい

## Stop conditions

次のときだけ Founder に戻す。

- 実名候補や外部連絡が必要
- public に本当に約束する文言を確定する
- 思想や経営判断として採る / 捨てるを決める
- 支援や権利に関わる高リスク境界を越える

- `/review/operating-loops` を、今後の operating map の基準ページにする
- `NBL-EXECUTIVE-START-HERE.md` からも参照できるようにする
- `relaunch home` と `next horizon` を、この loop map の中で読む
