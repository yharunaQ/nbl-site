# NBLサイト設計思想

作成日: 2026-04-04

---

## NBLが取り組む問題

**インクルーシブ雇用支援** ── 日本の職場において、障害・難病・機能的多様性を持つ人が仕事に参加し続けられるようにすること。

この問題は5つの相互に連動する領域で起きている：

1. 個人の仕事設計（機能プロフィールと仕事要求の不整合）
2. 支援実践（効果的支援を実施できない支援者の問題）
3. 職場・組織設計（多様な機能プロフィールを前提とした環境設計の欠如）
4. 制度・連携アクセス（使える支援・ネットワークへの接続の失敗）
5. 地域・社会構造（地域格差・制度設計・企業行動の問題）

これらは縦割りに切り分けられるものではない。個人の就労困難は組織設計の問題でもあり、地域の支援構造の問題でもある。NBLはこの5領域に対して一体として責任を持つ。

---

## コアにあるもの：専門知識ネットワーク

NBLのコアは、今回の開発で確立した**エビデンスに基づく専門知識ネットワーク**である。

### 知識ネットワークの基盤データ

| データ | 規模 | カバレッジ |
|---|---|---|
| 当事者調査（employment_survey） | n=4,553 | 障害・難病の就労困難・未解決課題 |
| 当事者調査（nanbyo_survey） | n=4,523 | 難病特有の就労困難・制度アクセス |
| 支援者調査（toku18） | n=3,053 | 効果的支援実践・GLM分析・地域差 |
| 支援者調査（nanbyo支援者） | n=535 | 難病支援の実践 |
| 外部知識統合（G1-G6） | — | IPS/SE・組織変革・制度・ピア学習 |
| FCHMAアトラス | 8D×6M | 因果構造の体系化 |

### 知識ネットワークの範囲

このネットワークが扱える問いは、27フレームで示される典型的状況をはるかに超えている。

- **27フレームガイドブック**: 典型的な状況のサブセット。個別状況への入口として機能するが、知識ネットワーク全体の断面に過ぎない
- **知識ネットワーク本体**: 個別的・複合的・非典型的な状況に対応できる。機能的困難の因果構造（FCHMAアトラス）に基づき、問いの組み合わせに応じて個別の答えを生成できる

### 射程の定義

知識ネットワークの射程は**インクルーシブ雇用支援**にある。

- 従来の「障害者雇用枠・就労支援制度の活用」にとどまらない
- 仕事をどう設計するか、職場をどう整えるか、という設計問題として扱う
- その設計知識は、障害者雇用の現場で蓄積されたが、適用対象はより広い

## サイト設計の原則

### 原則1：知識ネットワークが中心、アクセス経路が複数

サイトは「誰向けのセクション」を並べる構造ではなく、同一の知識ネットワークに対して複数の入口を設ける構造とする。

- 当事者として困っている人 → 「自分の状況を整理する」入口
- 支援する立場の人 → 「この状況でどう動くか」入口
- 職場・組織を変えたい人 → 「何を変えればよいか」入口
- 制度・政策を考える人 → 「何が構造的問題か」入口

どの入口から入っても、同じ知識ネットワークにたどり着く。同じ問いに対する答えが、立場によって違う見え方で示される。

### 原則2：縦割りを作らない

- セクションを「当事者用」「支援者用」「管理職用」と分離しない
- NBLの責任は問題領域全体に対して一体的。サイト構造がその一体性を体現する
- 現場の問題は常に複数の領域にまたがる。サイトもその複雑さに対応する

### 原則3：27フレームは入口の一つ

- 27フレームガイドブックは「典型的状況の地図」として有用だが、知識ネットワークの全体ではない
- 非典型・複合的・個別的な状況はAI（知識ネットワークへの対話的アクセス）で対応する
- フレームとAIは知識ネットワークへの二つのアクセス方式であって、別々のプロダクトではない

### 原則4：空論にしない根拠として知識ネットワークを使う

すべての主張・提案・ツールは、知識ネットワーク（実データ由来）に根拠を持つ。
「インクルーシブ雇用が重要」という理念は語らず、「この職場設計がこの理由で機能する」というエビデンスを示す。

## サイトの機能構成（原則から導かれる）

### コア機能

**① 知識ネットワークへの対話的アクセス（AI）**
- 個別状況を入力すると、知識ネットワークから関連する知見と具体的な一手が返ってくる
- 当事者・支援者・管理職・HR担当者——誰が使っても機能する
- 現在の `/jac/next` がこの機能の原型。今後はインクルーシブ雇用全体をカバーする方向に拡張

**② 27フレームガイドブック（典型状況への入口）**
- 典型的な状況パターンを一覧化したリファレンス
- 「自分の状況に近いフレームを探して読む」という使い方
- 当事者・支援者どちらにも機能する（読み方の案内を変える）

**③ 問題領域別の知見まとめ（エビデンス可視化）**
- 5問題領域それぞれについて、知識ネットワークが示すエビデンスをまとめた読み物
- 「地域格差の実態と構造」「効果的支援実践の要件」「組織設計の変数」等
- 政策・組織・研究文脈での利用を想定

**④ 実践知ライブラリ**
- Q1支援者の実践語り・事例
- 「この状況でこう動いた」という具体例のデータベース
- 知識ネットワークを実践として見せる

### ナビゲーション設計

「あなたは誰ですか」ではなく「何について知りたいですか」を入口にする。

```
あなたの状況を整理する     → AI（対話）または 27フレーム（一覧）
実践方法を知る            → 実践知ライブラリ + フレームの「外部と一緒に考える場面」
職場・組織を変える         → 問題領域別エビデンス（組織・環境設計）
制度・政策を考える         → 問題領域別エビデンス（構造・地域）
NBLの知識基盤について      → データと方法論の説明
```

## 知識ネットワークの継続的更新：3つのループ

専門知識ネットワークは静的な資産ではない。最初から更新・改善の仕組みが組み込まれていることが、知識の質を保つ条件である。

### ループ1：外部知識更新ループ

国際的なインクルーシブ雇用のガイダンス・エビデンス・雇用主実践を継続的に収集し、知識ネットワークの差分として取り込む。

**継続監視対象の外部レーン**（`jac-evidence-ops-loop-2026-03-26.md` に定義）:
- 職場調整プロセス（US: JAN/EEOC、UK: GOV.UK、EU、Canada、Australia）
- 雇用主向け実践ツールキット（EARN等）
- 国内制度改正・診療報酬改定・判例

**運用ルール**:
- 新規ソースを知識ネットワークに追加するかどうかの判断は創業者が行う
- source refresh → normalization → claims更新 → product canonへの反映はAI側で進める
- 何がstaleか・どの領域のカバレッジが低いかを定期的に可視化する

### ループ2：実ケース学習ループ

AIとの対話・相談事例から「何が機能して何が外れたか」を記録し、知識ネットワークの精度を改善する。

**設計**（`fchma-runtime-learning-loop-2026-03-31.md` に定義）:
```
相談事例の構造化 → 介入提案 → 結果の記録 → 次ケースへの反映
```

**現在の実装状態**:
- `lib/fchma/learningSummary.ts` — レビュー決定の集計・フィードバックのアウトカムパターン化
- `references/jac/feedback/` — フィードバック蓄積
- **次のステップ**: 学習サマリーをPostgreSQLに書き込み、介入優先度のランキングをモデル推論にフィードバックする（現在は記述的サマリーにとどまる）

**フィードバックから見るべきもの**:
- どのフレームが実状況で外れているか
- どの説明が使いやすかったか（utilityの向上）
- re-framingが必要なシグナル（既存フレームで分類できない事例の蓄積）

### ループ3：一次データ更新ループ

新たな調査データ・縦断データが取得できたとき、知識ネットワークの基盤を更新する。

**現状の課題**:
- 現在の知識ネットワークは横断データ（toku18 n=3,053等）に基づく。縦断データ（就労後の経過追跡）は未収集
- 企業側データ（採用・定着の実態）は別途収集設計が必要
- AIシステムの利用ログは将来の縦断的学習データになり得る

**運用ルール**:
- 新規一次データの取得・分析は別プロジェクトとして設計し、完了後にネットワークへ統合する
- 知識ネットワークの更新履歴は文書化し、何がいつどのエビデンスで変わったかを追跡可能にする

### 3ループの関係

```
外部知識更新ループ ──→ 知識ネットワーク ←── 一次データ更新ループ
                              ↕
                    実ケース学習ループ（AI相談・フィードバック）
```

知識ネットワークは3方向から継続的に改善される。どのループが主軸になるかは時期によって異なるが、すべてが常時動いていることを前提に設計する。

## 開発ロードマップ

### 第一段階：現行「なんちゃって版」を完成版に置き換える

現在公開中の各プロダクトは、FCHMAによらない暫定版である。第一段階はこれらを今回完成した知識ネットワークに基づく版に置き換えることが目的。

| 現行プロダクト | 状態 | 第一段階での対応 |
|---|---|---|
| `/jac/next` AI対話UI | FCHMAによらない暫定版 | 完成版知識ネットワーク対応に更新して公開 |
| HTMLガイドブック・ダウンロード版 | 旧26フレーム版 | 27フレームv3（`jac-27-frame-edition.md`）に更新 |
| フレーム一覧ページ（一覧性の高い表示） | 旧版 | 27フレームv3ベースに更新 |
| 27フレームインフォグラフィック等 | 旧版 | 必要に応じて更新（完全刷新は不要） |

**第一段階の完了条件**: 公開中のすべてのプロダクトが、完成した知識ネットワーク（FCHMAアトラス+当事者・支援者データ統合）に基づいていること。

---

### 第二段階以降：個々の支援者・職場を超えた課題への対応

今回の分析が明らかにしたことの多くは、個々の支援者や職場レベルの取組だけでは解決できない構造的・社会的な問題である。第二段階では、この知識ネットワークが持つ固有の知見を、そのスケールの問題に対応する情報・ツールとして提供する。

#### 第二段階コンテンツの方針：「日本のデータから」という根拠の強み

今回の知識ネットワークには、海外知見を「輸入する」のではなく、**日本の実データから独立して再発見した**という特徴がある。

**IPS/SEの例**:
- 従来の説明: 「IPS/SEという国際エビデンスがある。日本も取り入れるべき」
- 今回可能になった説明: 「日本の支援者・当事者データが示す有効な実践の構造は、IPS/SEが国際的に確認した原則と独立に整合している。つまり日本の実態に即した取組がどうあるべきかを、日本のデータから示せる」

この違いは大きい。「外国の輸入」への抵抗を回避するだけでなく、日本の制度・文化・地域特性に合わせた**精度の高い実践指針**を提示できる。

#### 第二段階で対応できる課題領域（知識ネットワークに根拠あり）

**① 支援実践の構造的問題**（Q2→Q1転換）
- 71.9%のQ2支援者が意欲はあるが実施できない
- Q1転換の有効経路（実践経験r=0.327、ピア学習、連携体制参加）はデータで示せる
- 個々の支援者向けではなく、支援機関・研修設計・政策向けの知見として提供できる

**② 地域格差の構造的問題**（北海道33% vs 香川5.3%）
- 格差の正体は「意識の差」ではなく「実践経験の蓄積環境の差」
- 「参加しているが転換しない」中国・四国パラドックス（参加率最高・転換効率最低）
- 地域別の介入優先事項・連携体制設計のあり方を示せる

**③ 組織設計の問題**（上司・職場文化が最大変数）
- Q1-Q2差の最大規定因子は上司・職場文化（+0.131）。機関ミッション（+0.118）が続く
- 管理職・機関長が具体的に何を変えればよいかをデータで示せる

**④ 職場設計のインクルーシブ化**（27フレームの先にあるもの）
- 27フレームの仕事設計知識は、障害者雇用の文脈で培われたが、適用対象はより広い
- AI時代の生産性議論に向けて「多様な機能プロフィールを前提とした仕事設計」の知見を提供できる

#### 第二段階の開発順序

知識ネットワークのカバレッジと社会的インパクトの両面から優先順位をつける。

1. **Q2→Q1転換支援コンテンツ**（支援者向け）: 知識基盤が揃っている・インパクトが大きい
2. **地域格差可視化ツール**（政策・機関向け）: データがあり・日本固有の知見
3. **組織診断・変革ガイド**（管理職・機関長向け）: Q14データ活用
4. **IPS/SE日本版実践ガイド**（支援機関・制度設計者向け）: 日本データからの独立発見として

---

### 何を作らないか

- 現在の知識ネットワークが根拠を持たない領域のコンテンツ（空論の排除）
- 「誰向けセクション」というロール別の縦割り区画（知識は一体）
- 海外知見の単純紹介・翻訳（日本データからの独立発見として提示できるものに絞る）
