## 1. 設計の前提：「究極」とは何か

### 現在の就労支援が「究極でない」理由

調査分析が明らかにした構造的問題：

**当事者側（13クラスタ）の問題**:
- 難病・障害の種類×就労困難性の組み合わせが複雑で、一律の支援では対応できない
- 支援情報へのアクセス格差（C12「開示困難型」C16「孤立型」は支援に辿り着けない）

**支援者側（4象限）の問題**:
- 71.9%が「連携志向理念あり・実施不可（Q2）」：意欲があるのに動けない
- Q2が集中している地域（中国・四国: 78.2%）は当事者も支援を受けにくい
- C0（医療機関: n=1,044）は就労支援に診療報酬上のインセンティブがない

**システム設計上の問題**:
- 「何が有効か」の知識（L3）はあるが「なぜ実践が広がらないか」（L1-L2）の知識がない
- 地域差（北海道33% vs 香川5.3%）が未解消：どこに生まれたかで支援の質が6倍違う

### 「究極」の定義

**究極の就労支援AI = 以下の3つを同時に実現するAI：**

```
① 「誰が」困っているかを精確に理解できる（当事者の個別性への対応）
② 「誰が」支援できるかを把握している（支援者の実践力の現実を踏まえた接続）
③ 「なぜ支援が届かないか」の構造的原因を特定し、解消できる（制度・組織への働きかけ）
```

## 3. Layer A: 当事者支援レイヤー（現行拡張設計）

- 44マニフォールドパターンからの類型化
- 介入仮説の生成

### 拡張設計（26フレーム接続）

**保留フレームの解消**（26フレームメモリ参照）:

| 保留フレーム | 解消根拠（今回の分析） |
|---|---|
| フレーム13（学習→仕事の接続） | C9・C12クラスタの移行準備パターン + IPS「place-then-train」 |
| フレーム14（実習→採用の橋渡し） | supports.md「段階設計」原則4 + IPS早期就職の根拠 |
| フレーム18（情報共有の線引き） | C12「難病・開示困難」クラスタ分析 + G3論拠3（同意ベース情報提供） |
| 追加B（就労意欲回復支援） | C2「全方位困難」クラスタ narrative + IPS原則1（訓練準備主義への対抗） |

- 地域の連携体制マップへの誘導
- C0支援者への「医療機関の支援者との連携」ガイド提供

## 4. Layer B: 支援者サポートレイヤー（新設設計）

### ターゲット

| ターゲット | 状態 | 必要な知識AI機能 |
|---|---|---|
| Q2支援者（n≈2,196） | 意欲あり・実施不可 | 「次の一手」特定 + 連携開始サポート |
| C0a支援者（n≈781） | 医療機関・無関心 | 連携開始プロトコル + 最初の一歩ガイド |
| C0b支援者（n≈178） | 組織的否定状態 | 管理職説得素材の提供 |
| C0c支援者（n≈80） | 地域インフラ不在 | 広域連携・遠隔接続の経路提示 |
| Q1支援者（n≈635） | 実践者 | 事例の言語化・ピア学習のファシリテーション支援 |

### 主要機能

**機能B-1: 「次の一手」特定AI**

入力: 支援者の現状記述（「〇〇の患者さんがいて、就労を希望しているが…」）
出力:
- FCHMAによる当事者の類型化（どのクラスタか）
- 「今の状態でできること/できないこと」の整理
- 「最初に連絡すべき機関」と「連絡の仕方」
- 「この先の想定される流れ」のシナリオ提示

**機能B-2: Q2→Q1転換コーチング**

入力: 「就労支援を始めたいが壁がある」という相談
出力:
- 壁の診断（L1制度/L2組織/L3学習/L4連携のどのレベルか）
- レベルに応じた突破策の提示
- 「今週できる最小アクション」の特定

**機能B-3: 地域連携体制マッチング**

入力: 支援者の機関種別 + 都道府県
出力:
- 地域内の機能する連携体制マップ（Q13データ + 地域差データ活用）
- 「この地域でQ1支援者が最も参加している連携体制」の推薦
- 初回連絡のスクリプト

**機能B-4: 事例言語化支援（Q1支援者向け）**

Q1支援者の実践知をナレッジベース化する仕組み：
- 支援者が「成功した/難しかったケース」を入力
- AI がFCHMA構造で整理・匿名化
- 他の支援者のピア学習素材として蓄積

→ **Q1支援者が知識を「生産」し、Q2支援者が「消費」する循環エコシステム**

## 5. Layer C: 制度・組織変革レイヤー（将来設計）

### ターゲット

- 医療機関・保健機関の管理職・機関長
- 自立支援協議会・地域就労支援ネットワークのコーディネーター
- 都道府県・国の政策立案者

### 主要機能

**機能C-1: 地域の「就労支援ギャップ」可視化ダッシュボード**

データ根拠: 都道府県別Q1率（北海道33% → 香川5.3%）
出力:
- 「あなたの都道府県の就労支援実践率：○%（全国○位）」
- 「Q2が多い地域で最も機能していない連携体制：○○」
- 「介入によって最も改善が期待できる障壁：○○（推定効果量: +X%）」

**機能C-2: 管理職向け「就労支援業務化」の説得素材生成**

入力: 機関の種別（病院/クリニック/保健所等）
出力:
- 「この機関が就労支援連携を業務化した場合の患者アウトカム改善の推計」
- 「同種機関で既に業務化した事例の整理」
- 「診療報酬上の活用可能な加算の整理」

**機能C-3: 政策提言素材の生成**

入力: 政策的な問い（「就労支援を医療に組み込むには何が必要か」）
出力:
- 定量エビデンスのサマリー（Q1-Q2差分析 + IPS効果量）
- 「診療報酬に就労支援加算が必要な根拠」の構造的説明
- 国際比較（英国・欧州の医療-就労支援統合モデル）

## 7. 追加データ分析が必要な領域

### 分析残課題（知識品質向上のために）

**分析残1: 当事者×支援者の直接マッチング検証**
- 現在: 機関種別をブリッジとした間接推計
- 理想: 同一ケースの当事者記述と支援者記述のペアリング（データ上は困難）
- 対応策: 「当事者クラスタ→最適支援者タイプ」の専門家評価によるバリデーション

**分析残2: 地域別の連携体制参加率マップ（問13 × 都道府県）**
- 現在: Q1/Q2別の全国平均参加率
- 必要: 「どの地域にどの連携体制が機能しているか」のマップ
- データ: toku18の問13 × 都道府県コードでクロス集計可能

**分析残3: C0b介入の効果推計**
- 現在: C0bの状態記述（ミッション=0.192）のみ
- 必要: 「管理職への介入前後の比較」に相当するデータ（現行データにはない）
- 対応策: 先行研究（医療機関での組織変革効果）の参照

**分析残4: 時系列データの欠如**
- 現在: 全データが横断的（一時点の調査）
- 問題: 「Q2→Q1転換が実際にどのプロセスで起きるか」は縦断データがないと検証できない
- 対応策: 知識AIの利用ログから「転換の兆候」を学習する設計（将来的フィードバックループ）
