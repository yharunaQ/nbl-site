# AI-Native Marketing Synthesis

更新日: 2026-03-21
Status: actioned

## Working thesis

新生NBLは、旧来型の会社らしさへ寄せて trust を取るより、`AIが駆動し、人が責任を持つ` という operating truth を先に見せた方が強い。

ただし、`AIが動かしている` 単独では不安が勝ちやすい。
public では必ず次の 3 点を同じ画面で見せる。

1. AI が何を進めるか
2. 人が何を止め、何に責任を持つか
3. 何が artifact として残るか

## Why this still has upside now

- AI-first / AI-native の勝ち筋は、単なる新しさではなく `control + handoff + improvement loop` を visible にすることに寄っている
- NBL にはすでに `AI-operated virtual team`、`Human-in-Command`、`social OS` という内部原則があり、後付けの marketing fiction ではない
- 障害・難病と仕事設計の領域は、`仕事 / 情報 / 運用 / 支援 / 制度` の設計問題が立ち上がりやすく、AI-native operating layer の差分が見せやすい

## Immediate moves

### 1. Make the better home page public

- `temporary` ではなく `relaunch` を公開トップにする
- 既にある `RelaunchPublicHome` を front door として使う

### 2. Repeat one sentence everywhere

- 基本文:
  - `AIが駆動し、高リスク判断と対外責任は人が持つ。`
- Home / What We Do / About / Operating Model / Enterprise で同じ意味を繰り返す

### 3. Keep the difference concrete

- `AI-native` を抽象語で終わらせず、`論点整理 / draft / 記録化`
- `Human boundary`
- `artifact / decision / resource`

### 4. Enterprise needs an explicit non-replacement note

- 既存支援を置き換えない
- 法的・医療的最終判断を AI に委ねない
- 高リスク個別判断の単独窓口に見せない

## Changes applied in this round

- public home variant を `relaunch` に変更
- Home hero と evidence area を `AIが駆動し、人が責任を持つ` へ sharpen
- `What We Do` hero に responsibility note を追加
- `About` hero と key points に trust / boundary language を追加
- `Operating Model` hero に trust = visible boundary の note を追加
- `For Enterprise` に `NBLが置き換えないもの` を追加

## Next recommended moves

1. Home の `How the site improves` に更新日や recency signal を薄く足す
2. `Contact` を `buy` 導線より `fit を確かめる` 導線としてさらに整える
3. `/resources` に `先に役立つ artifact` を 2-3 本追加し、AI-native の差分を公開資源側でも感じられるようにする
4. founder-facing outreach では `AI-native social OS` より `仕事設計と運用設計の translation layer` を主言語に使い分ける
