# External Connection And Marketing Strategy

更新日: 2026-03-19

## Purpose

Founder 依存を減らしつつ、`desk research -> market hypothesis -> site build backlog` をつなぐための内部メモ。

狙いは次の 3 つ。

1. NBL が外部との接続をどこから作るべきかを、制度・現場課題・既存支援の現状から整理する
2. `相手に役立たないものを売り込まない` ために、public site が先に返すべき価値を固定する
3. Founder がやることを `実名候補 / public promise / outreach 実行` に絞る

### Inference

- 企業側の困りごとは `理解不足` だけではない。`仕事の切り出し`、`運用設計`、`配慮運用`、`支援機関との接続`、`継続就労のマネジメント` がセットで詰まっている。
- したがって NBL は、`一般的な相談窓口` や `既存支援の代替` として出るより、`仕事設計と運用設計の translation / structuring layer` として見せる方が fit しやすい。
- 既存支援が豊富なぶん、NBL の差分は `全部やること` ではなく、`複数の支援や判断主体のあいだで論点を整理し、再利用可能な artifact を残すこと` にある。
- 初期 partner は、1回限りの助言先より `repeated use` と `cross-case learning` が起こる相手の方がよい。既存仮説どおり、`employer-facing intermediary first` は依然として筋がよい。

### Normative

- public site は `広く売る` ためのものではなく、`fit する相手に、自分ごととして役立つ入口を返す` ためのものにする。
- public copy は `診断名ごとの万能解` を示さない。`人 / 仕事 / 環境 / 支援 / 時間 / 制度` を分けて見る site language を維持する。
- NBL は `相談の受け皿を独占する` ように見せず、必要に応じて既存制度・既存支援へ接続する boundary を見せる。

### Recommendation

- site の最初の主題は `障害者雇用そのもの` より、`働きづらさを仕事設計として扱う` に置く。
- そのうえで、企業向けの実務テーマは次の 3 本で固定する。
  1. `適当な仕事がない / 切り出せない`
  2. `合理的配慮や相談導線が属人化している`
  3. `既存支援と社内運用をつなげられない`
- CTA は `買う` より先に `理解する / 試す / fit を確かめる` に寄せる。
- 外部接続の初期目的は `sell` ではなく `fit evaluation` に置く。

  - `NBL は既存支援を置き換えず、仕事設計と運用設計を整理する` という positioning

## Bias / Discrimination Risk

- Risk level:
  - medium
- Risk factors:
  - `障害者雇用のコツ` のような一般化に寄ると、個別文脈を潰しやすい
  - `AI で効率化` を前に出しすぎると、雇用管理や配慮の責任所在が曖昧になる
  - `相談窓口` に見せると、既存制度との役割衝突や過剰期待が起きやすい
- Guardrails:
  - `診断名 -> 解決策` の直結を避ける
  - `建設的対話` と `個別性` を前提にする
  - 既存支援へつなぐ boundary を常に併記する

## Market Hypothesis

### Strongest first audience

- `Employer-facing intermediary`
- 条件:
  - employer network を持つ
  - named operational owner がいる
  - NBL を `人の相談外注` でなく `operating layer` として理解できる
  - human review / external escalation を受け入れられる

### Why this audience first

- 企業の困りごとは `単発質問` ではなく、`雇用前 / 配属 / 配慮 / 定着 / 支援連携` をまたぐため、intermediary の方が repeated use に乗りやすい
- 公的支援や無料支援が既にあるため、NBL 単体で `全部請ける` より `現場の論点整理と接続` に寄せた方が差別化しやすい
- 中間支援者は `複数企業の共通パターン` を見られるため、artifact compounding と相性がよい

### Second audience

- `Design-forward employer`
- 条件:
  - 法定雇用率対応だけでなく、work redesign appetite がある
  - 人事だけでなく現場 / DX / 経営企画の sponsor がいる
  - 1 本目の workflow lane を絞れる

### Third audience

- `Research / policy lighthouse`
- 条件:
  - legitimacy を補える
  - field translation に寄与する
  - revenue lead と混同しない

## Site Build Implications

### The site should answer first

1. `この組織は何を置き換えず、何を整理するのか`
2. `うちの課題にどう関係するのか`
3. `いま公開されている資源だけで何が持ち帰れるのか`
4. `fit しない場合はどこへ向かうべきか`

### Safe build order

1. `/for-enterprise`
   - `既存支援との関係` を明文化する
   - `NBL が置き換えないもの` を visible にする
   - `仕事が切り出せない / 相談が属人化 / 既存支援につながらない` の 3 pain で読み替える
2. `/resources`
   - public-safe な実務資源を 3 本作る
   - `合理的配慮を職場設計として見る`
   - `継続就労と情報共有の設計`
   - `仕事を切り出せない時の観点整理`
3. `/what-we-do`
   - `向いている相手 / 向いていない相手` をより明確にする
   - `not labor outsourcing` を強める
4. hidden review
   - partner fit page
   - existing-support map
   - outreach-to-site handoff note

### Content posture

- sales-first にしない
- `相手の困りごと -> まず返す整理 -> 次に話す条件` の順にする
- artifact-first にする
- `Human review boundary` を全ページで消さない

## Distribution Strategy

### Primary lane

- targeted outreach
- sequence:
  1. short outreach note
  2. one-page package brief
  3. boundary note
  4. fit evaluation conversation

### Secondary lane

- article / search / referral からの inbound
- ここでは `売り込み` より `公開資源で先に役立つ` を優先

### What not to do

- generic `障害者雇用コンサルです` 化
- 診断カテゴリ別の扁平な訴求
- 価格先出し
- `何でも相談してください` wording

## What AI Team Can Continue Without Founder

- official source の継続収集
- site copy と hidden review draft の整備
- partner scorecard / tracker / dossier の改善
- public-safe な resource page の素案作成
- outreach pack の更新

## What Needs Founder

- 実名候補の投入
- public で本当に約束する表現の採否
- 実際の outreach 実行
- irreversible な提携判断

## Minimal Founder Contribution

Founder にお願いしたいことは多くない。次の 4 つで十分。

1. `Name`
   - A1 / A2 / B1 / C1 に入れられそうな実名候補を各 1-2 件
2. `Keep / Adjust`
   - `AI-native social OS` と `職場設計` のどちらを public 主言語に置くか
3. `Example`
   - 実際に `これは役立つ / これは役立たない` と感じた 2-3 事例
4. `Yes / No`
   - outreach を始めるか

## Provisional Next Action

- Minimal safe action now:
  - このメモを基準に `enterprise inbound` と `partner discovery` を接続する
  - `/for-enterprise` の次の改善点を hidden review として先に固める
  - A:2 / B:1 / C:1 の候補 slot に必要な条件だけ先に入れる

## Bottom Line

- `独自に調査して、戦略を立てて、サイト構築を進める` 方針は妥当
- ただし、進める対象は `広く売るサイト` ではなく、`fit する相手に役立つ site + discovery system`
- Founder の仕事は、全部考えることではなく、`Name / Keep-Adjust / Example / Yes-No` を返すこと
