# 就業共通設計 化 改修憲章（JAC 26フレーム）

更新日: 2026-03-02

## 1. 目的

- 26フレームを「障害者雇用の問題対応」中心の見せ方から、
  「誰にも起こりうる就業設計課題を先回りで整える」共通設計モデルへ再定義する。
- 障害・難病領域で先に可視化された困難を、社会全体の就業設計へ還元する。
- ただし、合理的配慮や法制度文脈を弱めず、個別相談の必要性を明確化する。

## 2. 非目的

- 26フレーム自体の即時廃止・全面再クラスタリング（別トラックで監査継続）。
- 「共通設計」を理由に個別配慮・法的義務を一般論へ吸収して曖昧化すること。
- 当事者の経験を匿名化の範囲を超えて一般消費コンテンツ化すること。

## 3. 中核定義

`就業共通設計`:
- 障害や難病で先に見えやすい就業上の困難を、
  誰にも起こりうる設計課題として捉え直し、
  変動・移行・職場運用をあらかじめ整える考え方。

## 4. 言い換え原則

- 原則A: 困難の原因を「個人属性の固定説明」ではなく「条件×業務×運用の相互作用」で記述する。
- 原則B: 先手の運用設計（予防）と、発生後の再設計（復元）を分けて示す。
- 原則C: 「共通設計レイヤー」と「個別配慮レイヤー」を混同しない。
- 原則D: 推奨文は必ず条件付きで書く（person/job/environment/support/time/institution/evidence）。

## 5. ガードレール（必須）

- 診断名のみで可否を断定しない。
- 合理的配慮の法的義務を「任意の配慮」へ弱める表現を使わない。
- 国・法域差を無視した制度記述をしない。
- 当事者由来の記述を実名・地域・機関名など再識別可能情報と結びつけない。

## 6. 出力の二層構造（全26フレーム共通）

- レイヤー1: 共通設計（誰にも起こりうる設計課題）
  - 何が詰まるか
  - 早期に整える設計ポイント
  - 現場運用での再評価トリガー
- レイヤー2: 個別最適化（当事者条件・法域条件）
  - 追加確認質問
  - 適用条件と非適用条件
  - 個別相談へ渡すべき条件情報

## 7. 完了条件（Definition of Done）

- 26/26フレームで以下を満たす:
  - 名称・要約・ポイントが就業共通設計語彙で統一されている
  - 既存根拠（data2/raw_data/web-cache/GLM）との意味不整合がない
  - 差別・過度一般化リスク監査で重大指摘がない
  - ガイド/冊子/JAC導線の説明が同一思想で整合している

## 8. 変更管理

- 文言変更は「辞書（旧→新）」を単一ソースとして管理する。
- 変更理由は「根拠整合」「可読性」「誤用リスク低減」のいずれかに分類する。
- `web-cache` や curated local note の追加で新しい根拠束が増えた場合は、
  まず source impact 監査で 26フレームへの吸収率を確認する。
- 吸収率が低い source が出た場合は、
  microcopy パッチだけで閉じず、フレーム境界・関連フレーム導線・必要なら再クラスタリング候補まで戻って検討する。
- 監査落ち時は、パッチ修正ではなく辞書と原則に戻って再編集する。
