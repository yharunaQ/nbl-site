## 使いどころ

- 企業単独では重い配慮や支援案を出す前に、誰が何を持つかを先に固定したい時。
- `p-support-service-navigation`、`p-worktrial-transition`、`p-manager-checkin`、`p-disclosure-boundary`、`p-mental-fluctuation-plan` のいずれかが関わる時。
- person / job / environment / support / time / institution / evidence の確認が揃う前に、責任線だけでも崩さず進めたい時。

## 記入ヒント

### 支援接続アーキテクチャ `p-support-service-navigation`

- カード内に残す最小要素: 支援接続案は期限・責任者つきで見る / 制度要件は法域・自治体確認前提で使う
- 先に確認する質問: 直近1か月で止まっている支援手続きは何か？ / 窓口ごとの役割分担は明確か？
- 前提条件: 利用可能な制度一覧を把握できる / 窓口間連携に同意がある
- 関連する共通運用: 実施可能性トリアージ / 役割分担の明文化 / 同意・情報共有の最小化 / ケース会議の発動条件 / 定着支援と戻し先
- 詳細の置き場: 地域支援オーケストレーション別ガイド

### 相談運用ガバナンス `p-manager-checkin`

- カード内に残す最小要素: 外部エスカレーション先があるかだけ示す / 社内責任線と相談導線を可視化する
- 先に確認する質問: 現在の相談導線は誰が担っているか？ / 相談内容が業務変更へ反映されるまでの遅延は何日か？
- 前提条件: 相談窓口の担当が明確 / 業務変更権限を持つ管理者が関与できる
- 関連する共通運用: 役割分担の明文化 / ケース会議の発動条件 / 定着支援と戻し先
- 詳細の置き場: 地域支援オーケストレーション共通レイヤー

### 実習採用ブリッジ `p-worktrial-transition`

- カード内に残す最小要素: 採用後1から4週の支援体制を実習評価とセットで見る / 実習制度の要件確認は法域前提で行う
- 先に確認する質問: 採用後に増える業務負荷は何か？ / 実習評価のどの項目を採用後KPIに転用するか？
- 前提条件: 実習評価が記録されている / 採用側の運用責任者が定義されている
- 関連する共通運用: 実施可能性トリアージ / 役割分担の明文化 / 定着支援と戻し先
- 詳細の置き場: JACカード本文

### 情報開示レイヤー設計 `p-disclosure-boundary`

- カード内に残す最小要素: 支援体制とセットで開示量を判断する / 共有目的・共有範囲・見直し時点を最小共有で設計する
- 先に確認する質問: 配慮実装に必須な情報は何で、不要な情報は何か？ / どの役割まで共有する必要があるか？
- 前提条件: 情報共有ポリシーと責任者が定義されている / 現場が目的限定の情報共有ルールを運用できる
- 関連する共通運用: 同意・情報共有の最小化 / 役割分担の明文化
- 詳細の置き場: JACカード本文

### 悪化予兆ハンドリング `p-mental-fluctuation-plan`

- カード内に残す最小要素: 再評価導線と戻し先を示す / 初期サインと段階調整の閾値を明文化する
- 先に確認する質問: 初期悪化サインは何で、誰が確認するか？ / 段階調整の発動条件は定義済みか？
- 前提条件: 相談窓口と責任者が明確 / 緊急時ルートを運用できる
- 関連する共通運用: 同意・情報共有の最小化 / ケース会議の発動条件 / 定着支援と戻し先
- 詳細の置き場: JACカード本文

## 完了判定

- 「誰がやるか」が空欄のまま残っていない
- 企業内担当と地域支援担当が重複していない
- 戻し先が具体的な担当または会議単位で書かれている
- 法域と本人同意の範囲が未確認のままになっていない
