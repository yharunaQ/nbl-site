# JAC 地域支援オーケストレーション別ガイド（最小骨格）

更新日: 2026-03-07
状態: draft

## Holistic Positioning
- Scope of source: JAC 26フレームのうち、地域支援レイヤー圧が高い5カードを対象に、カード外へ逃がす実装運用を再整理した最小骨格。
- Covered lenses: difficulty_resolution / support_need_formation / symptom_work_interaction (partial)
- Missing lenses: difficulty_occurrence の個別 task 条件、自治体ごとの支援資源差、法政策上の義務判断

## What is currently usable
- Usable now (with conditions): JAC提案と同時に、地域支援体制、役割分担、戻し先をセットで示す共通運用。
- Not yet usable: 地域機関名のディレクトリ、自治体別制度要件、法的助言そのもの。

## Bias/Discrimination Risk
- Risk level: medium
- Risk factors: 地域資源の有無や企業側の実装余力を省略すると、「支援体制があれば実施できる」と過大評価しやすい。

## Additional information required
- Must-have questions: 既存支援者は誰か / 情報共有同意の範囲はどこか / 企業内担当者は誰か / 地域で使える資源は何か / 法域はどこか
- Nice-to-have questions: これまで試した支援の履歴 / 定着支援の頻度 / 再評価の閾値 / 通院や生活変動との関係

## Provisional next action
- Minimal safe action now: 企業へ重い配慮案を出す前に、役割分担と戻し先を1枚で固定する。
- Re-evaluation trigger: 役割未確定、同意未確定、期限未設定、地域資源未確認のまま進みそうな時。

## 2. 共通運用レイヤー

### 実施可能性トリアージ

- 目的: 企業単独で回るか、地域支援体制を添えないと止まるかを最初に見分ける。
- JACが担うこと:
- 配慮案だけでなく、誰が何を担うと実施できるかを最小単位で言語化する
- 企業単独で抱えにくい論点を、相談・制度・定着支援のどこへ接続するか示す
- 地域支援者が担うこと:
- 専門評価、制度要件確認、定着支援のどれが必要かを判断する
- JAC提案を地域資源の現実に合わせて実装可能な順序へ並べ替える
- 企業内で担うこと:
- 社内で担える範囲と担えない範囲を隠さず明示する
- 担当者、期限、再評価条件を決める
- 最小成果物: 役割分担付きの提案メモ 1枚
- 戻して見直す条件: 担当者が決まらない、期限が引けない、制度要件が曖昧な場合

### 役割分担の明文化

- 目的: JAC / 地域支援者 / 企業 / 本人 の境界を曖昧にしない。
- JACが担うこと:
- 企業内で回す項目と外部支援が必要な項目を分けて提示する
- 戻し先を含めた責任線を固定する
- 地域支援者が担うこと:
- ケース会議、同行支援、定着支援など外部側の実行単位を明確にする
- 支援の過不足が出た時の再調整窓口になる
- 企業内で担うこと:
- 現場管理者と人事の役割を分けて持つ
- 情報共有先と評価責任を混ぜない
- 最小成果物: 役割分担シート
- 戻して見直す条件: 「誰がやるか」が会議後に宙に浮く場合

### 同意・情報共有の最小化

- 目的: 必要配慮の実装に必要な最小情報だけを扱い、共有過多を避ける。
- JACが担うこと:
- 共有目的、共有先、見直し時点を分けて確認する
- 共有しない情報でも支援できる代替経路を残す
- 地域支援者が担うこと:
- 本人同意に基づく情報共有設計を支える
- ケース会議が必要な場合の参加者と記録ルールを整理する
- 企業内で担うこと:
- 配慮実装に不要な情報を持ち込まない
- 共有範囲と保存責任を社内で固定する
- 最小成果物: 共有範囲メモ
- 戻して見直す条件: 共有範囲が広がり続ける、目的が曖昧になる場合

### ケース会議の発動条件

- 目的: 迷った時の戻し先を前もって決め、個人の抱え込みを防ぐ。
- JACが担うこと:
- 再評価が必要な閾値を先に決める
- 会議が必要か、個別相談で足りるかを判断する
- 地域支援者が担うこと:
- 専門的見立てが必要な論点に応じて参加する
- 会議後の支援実装と経過確認を担う
- 企業内で担うこと:
- 現場だけで抱え込まず、再評価条件に達したら戻す
- 会議後の社内実装を引き取る担当者を置く
- 最小成果物: ケース会議トリガー一覧
- 戻して見直す条件: 不調再発、連絡遅延、役割不明、制度条件不明

### 定着支援と戻し先

- 目的: 一度決めた支援を固定せず、実施しやすさと再現性を継続点検する。
- JACが担うこと:
- 支援の実施状況と企業負担感を確認する
- 止まった時の再接続窓口を維持する
- 地域支援者が担うこと:
- 定着支援、再評価、必要時の職務再調整を支える
- 地域資源の変更や新たな支援導入を提案する
- 企業内で担うこと:
- 現場の負担と効果を定期的に共有する
- 中断理由を曖昧にせず、戻し先へ返す
- 最小成果物: 月次見直しメモ
- 戻して見直す条件: 想定より負担が高い、効果が見えない、連絡が途切れる場合

## 3. カード別接続メモ

### 支援接続アーキテクチャ `p-support-service-navigation`

- 地域支援の扱い: 別ガイドで扱う
- カードの役割: 就業共通設計では、人を選別する前に仕事の側を先に設計し、制度情報が散在していると、必要な支援へ接続できず就労移行が遅れやすい。この設計要素は、特性差・体調変動・ライフイベントの違いがある誰にでも起こりうる。
- このガイドで重点的に見る範囲: 地域支援オーケストレーション別ガイド
- カード内に残す最小要素:
- 支援接続案は期限・責任者つきで見る
- 関連する共通運用:
- 実施可能性トリアージ
- 役割分担の明文化
- 同意・情報共有の最小化
- ケース会議の発動条件
- 定着支援と戻し先
- 地域支援レイヤーの要約: 制度名だけを並べず、窓口順序・期限・役割分担まで一緒に示すと実施が止まりにくい。
- JACが担う部分:
- 止まっている手続き、期限、責任者を1枚で整理する
- 企業や本人に示す支援接続案を、次アクション付きで提示する
- 地域支援者が担う部分:
- 制度要件の確認、申請補助、窓口間連携を支える
- 同意に基づく情報共有とケース会議を必要時に組む
- 止まった時の戻し先: 窓口間で止まったら、JACが責任者と次回接点を再固定する。
- 個別相談で必ず確認する質問:
- 直近1か月で止まっている支援手続きは何か？
- 窓口ごとの役割分担は明確か？
- 次アクションの期限と責任者は誰か？
- 前提条件:
- 利用可能な制度一覧を把握できる
- 窓口間連携に同意がある

### 相談運用ガバナンス `p-manager-checkin`

- 地域支援の扱い: 共通レイヤーで扱う
- カードの役割: 就業共通設計では、人を選別する前に仕事の側を先に設計し、相談窓口が曖昧だと、困りごとが蓄積してから顕在化し、調整が後手になりやすい。この設計要素は、特性差・体調変動・ライフイベントの違いがある誰にでも起こりうる。
- このガイドで重点的に見る範囲: 地域支援オーケストレーション共通レイヤー
- カード内に残す最小要素:
- 外部エスカレーション先があるかだけ示す
- 関連する共通運用:
- 役割分担の明文化
- ケース会議の発動条件
- 定着支援と戻し先
- 地域支援レイヤーの要約: 管理者面談だけに負荷を集めず、外部支援へのエスカレーション先まで同時に固定する。
- JACが担う部分:
- 面談頻度、相談導線、業務変更までの責任線を可視化する
- 企業単独で抱えにくい論点を外部支援接続込みで提示する
- 地域支援者が担う部分:
- 専門評価、定着支援、ケース会議への参加で判断を補う
- 相談内容が医療・福祉・就労支援へまたがる場合の橋渡しを担う
- 止まった時の戻し先: 面談が形骸化したら、JACと管理者と地域支援者で役割を再分解する。
- 個別相談で必ず確認する質問:
- 現在の相談導線は誰が担っているか？
- 相談内容が業務変更へ反映されるまでの遅延は何日か？
- 連携先へのエスカレーション条件は明確か？
- 前提条件:
- 相談窓口の担当が明確
- 業務変更権限を持つ管理者が関与できる

### 実習採用ブリッジ `p-worktrial-transition`

- 地域支援の扱い: カード内に残す
- カードの役割: 就業共通設計では、人を選別する前に仕事の側を先に設計し、実習時の評価軸と採用後の運用条件が繋がっていないと、定着に失敗しやすい。この設計要素は、特性差・体調変動・ライフイベントの違いがある誰にでも起こりうる。
- このガイドで重点的に見る範囲: JACカード本文
- カード内に残す最小要素:
- 採用後1から4週の支援体制を実習評価とセットで見る
- 関連する共通運用:
- 実施可能性トリアージ
- 役割分担の明文化
- 定着支援と戻し先
- 地域支援レイヤーの要約: 実習評価だけで終えず、採用後1から4週の支援体制まで合わせて示すと移行しやすい。
- JACが担う部分:
- 実習評価を採用後の運用項目と初期KPIへ翻訳する
- 企業内担当者、不調時連絡、見直しタイミングを固定する
- 地域支援者が担う部分:
- 実習評価の補足、定着支援、職務再調整を支える
- 不調時の再評価とケース会議の再招集を担う
- 止まった時の戻し先: 採用後に負荷が跳ねたら、実習評価へ戻して再調整条件を見直す。
- 個別相談で必ず確認する質問:
- 採用後に増える業務負荷は何か？
- 実習評価のどの項目を採用後KPIに転用するか？
- 不調時の連絡・代替フローは明確か？
- 前提条件:
- 実習評価が記録されている
- 採用側の運用責任者が定義されている

### 情報開示レイヤー設計 `p-disclosure-boundary`

- 地域支援の扱い: カード内に残す
- カードの役割: 就業共通設計では、人を選別する前に仕事の側を先に設計し、必要配慮の実装には情報共有が必要だが、開示過多はプライバシー侵害リスクを高める。この設計要素は、特性差・体調変動・ライフイベントの違いがある誰にでも起こりうる。
- このガイドで重点的に見る範囲: JACカード本文
- カード内に残す最小要素:
- 支援体制とセットで開示量を判断する
- 関連する共通運用:
- 同意・情報共有の最小化
- 役割分担の明文化
- 地域支援レイヤーの要約: 開示量の判断を企業内だけで抱えず、必要最小限共有と支援接続をセットで設計する。
- JACが担う部分:
- 共有目的、共有相手、見直し時点を配慮実装に必要な範囲へ絞る
- 企業へは開示内容だけでなく、支援体制と戻し先もセットで示す
- 地域支援者が担う部分:
- 本人同意に基づく情報共有設計とケース会議運営を支える
- 共有しない情報でも支援可能な代替手段を提案する
- 止まった時の戻し先: 共有範囲で迷いが続く場合は、目的を再確認して最小共有へ戻す。
- 個別相談で必ず確認する質問:
- 配慮実装に必須な情報は何で、不要な情報は何か？
- どの役割まで共有する必要があるか？
- 本人同意と見直しタイミングをどう設計するか？
- 前提条件:
- 情報共有ポリシーと責任者が定義されている
- 現場が目的限定の情報共有ルールを運用できる

### 悪化予兆ハンドリング `p-mental-fluctuation-plan`

- 地域支援の扱い: カード内に残す
- カードの役割: 就業共通設計では、人を選別する前に仕事の側を先に設計し、悪化兆候の定義や連絡手順がないと、対応が遅れて離脱・長期休職リスクが上がりやすい。この設計要素は、特性差・体調変動・ライフイベントの違いがある誰にでも起こりうる。
- このガイドで重点的に見る範囲: JACカード本文
- カード内に残す最小要素:
- 再評価導線と戻し先を示す
- 関連する共通運用:
- 同意・情報共有の最小化
- ケース会議の発動条件
- 定着支援と戻し先
- 地域支援レイヤーの要約: 悪化時対応を社内ルールだけで閉じず、外部支援者の再評価導線を持つと運用しやすい。
- JACが担う部分:
- 初期サイン、段階調整、緊急時連絡の閾値を明文化する
- 企業単独で担えない対応を地域支援体制つきで提示する
- 地域支援者が担う部分:
- 再評価、定着支援、緊急時の伴走を支える
- 必要時に医療・福祉・就労支援との接続を調整する
- 止まった時の戻し先: 兆候が再発したら、初期サイン定義と支援頻度を見直す。
- 個別相談で必ず確認する質問:
- 初期悪化サインは何で、誰が確認するか？
- 段階調整の発動条件は定義済みか？
- 緊急連絡時の共有範囲は目的限定になっているか？
- 前提条件:
- 相談窓口と責任者が明確
- 緊急時ルートを運用できる
