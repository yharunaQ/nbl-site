更新日: 2026-03-07
状態: template

## 使いどころ

- 迷った時に誰を呼ぶか、いつ戻すかを事前に決めておきたい時。
- `p-manager-checkin`、`p-disclosure-boundary`、`p-mental-fluctuation-plan` で、支援判断を企業だけに閉じたくない時。
- 不調再発、共有範囲の迷い、連絡遅延、制度条件不明が起きた時の再評価条件を固定したい時。

## 会議前の最低確認

- 現時点で共有してよい情報は何か
- いまの業務影響はどこに出ているか
- 会議なしで戻せる論点か、専門見立てが必要な論点か
- 会議後に誰が社内実装を引き取るか

## 記入ヒント

### 相談運用ガバナンス `p-manager-checkin`

- カード内に残す最小要素: 外部エスカレーション先があるかだけ示す / 社内責任線と相談導線を可視化する
- 先に確認する質問: 現在の相談導線は誰が担っているか？ / 相談内容が業務変更へ反映されるまでの遅延は何日か？
- 前提条件: 相談窓口の担当が明確 / 業務変更権限を持つ管理者が関与できる
- 関連する共通運用: 役割分担の明文化 / ケース会議の発動条件 / 定着支援と戻し先
- 詳細の置き場: 地域支援オーケストレーション共通レイヤー

### 情報開示レイヤー設計 `p-disclosure-boundary`

- カード内に残す最小要素: 支援体制とセットで開示量を判断する / 共有目的・共有範囲・見直し時点を最小共有で設計する
- 先に確認する質問: 配慮実装に必須な情報は何で、不要な情報は何か？ / どの役割まで共有する必要があるか？
- 前提条件: 情報共有ポリシーと責任者が定義されている / 現場が目的限定の情報共有ルールを運用できる
- 関連する共通運用: 同意・情報共有の最小化 / 役割分担の明文化
- 詳細の置き場: JACカード本文

### 悪化予兆ハンドリング `p-mental-fluctuation-plan`

- カード内に残す最小要素: 再評価導線と戻し先を示す / 初期サインと段階調整の閾値を明文化する
- 先に確認する質問: 初期悪化サインは何で、誰が確認するか？ / 段階調整の発動条件は定義済みか？
- 前提条件: 相談窓口と責任者が明確 / 緊急時ルートを運用できる
- 関連する共通運用: 同意・情報共有の最小化 / ケース会議の発動条件 / 定着支援と戻し先
- 詳細の置き場: JACカード本文

## 完了判定

- 発動条件が抽象語だけで終わっていない
- 誰が判断するかと戻し先が同じ人に集中しすぎていない
- 24-72時間でやることが空欄になっていない
