# JAC ガイドブック 編集エージェント・スプリントパケット

更新日: 2026-03-07
状態: internal-editorial

## 位置づけ

- `observation`: 現在の冊子は、内容の厚みは出てきたが、まだ Web ツール由来の説明順と文体が前に出やすい。
- `inference`: 読者の疑問順で再構成し、図版・見開き・要約の強弱を入れると、理解速度と実装しやすさが上がる。
- `normative`: 根拠、法政策差、地域支援体制、個別条件は落とさず、読者が自然に読める順番へ並べ替える。
- `recommendation`: 知識設計と冊子編集を分離し、AI エージェントの役割分担で重点5章から先に仕上げる。

## 編集チーム

### Evidence Steward `evidence_steward`

- 役割: 根拠、法政策差、地域支援条件、個別条件を落とさずに編集へ渡す。
- 成果物: observation / inference / normative / recommendation を切り分けた根拠メモ。

### Developmental Editor `developmental_editor`

- 役割: 読者の疑問順で章のストーリーを組み直し、読み進める理由を作る。
- 成果物: 章の問い順、見開き構成、削る情報と残す情報の判断。

### Copywriter `copywriter`

- 役割: 技術説明を、読者がそのまま理解できる自然文へ変換する。
- 成果物: 章頭導入、見出し、図版キャプション、要約文の叩き台。

### Art Director `art_director`

- 役割: 図版、余白、強弱、視線誘導で「読み切れる見開き」へ変える。
- 成果物: 見開きラフ、図解指示、重要語の階層設計。

### Web Translator `web_translator`

- 役割: 冊子で良かった見出し順・図解・導線を、WebカードのUIへ逆輸入する。
- 成果物: ガイド画面へ戻す見出し、補助線、図解、導線の変更案。

## スプリントの進め方

1. `evidence_steward` が「落としてはいけない条件」を確定する。
2. `developmental_editor` が、読者の疑問順で章構成と見開き構成を決める。
3. `copywriter` が、章頭・小見出し・図版キャプションを自然文へ書き直す。
4. `art_director` が、図解・余白・強弱で読む順序を固定する。
5. `web_translator` が、冊子で効いた見せ方を Web ガイドへ逆輸入する。

## 編集ガードレール

- 診断名を主語にしない。仕事・環境・支援・時間の条件から書く。
- 「読みやすさ」のために法政策差や地域支援体制を消さない。
- 制度説明や支援機関説明は、それ自体を主役にせず、読者が動く判断のために使う。
- 章内で解けない論点は、戻し先を曖昧にしない。

- normative: 法政策差、地域支援体制、戻し先は、読者向けに言い換えても削除しない。
- recommendation: 下記の「絶対に落とさない条件」を本文・図版・補助線のどこかに必ず残す。

#### Copywriter

- recommendation: 窓口名の列挙から入らず、「まず何が止まっているのかを一枚で見る」で導入する。制度名は本文より図版側へ寄せる。
- recommendation: 先頭で使うべき読者の疑問は「制度や支援機関が多すぎて、結局どこに相談すればよいのか。どこで止まっているのか。」とする。

#### Art Director

- recommendation: 左ページを「止まりやすい3地点」、右ページを「接続ルート図」にする。担当者と期限を図版の主役にする。

#### Web Translator

#### Copywriter

- recommendation: 先頭で使うべき読者の疑問は「実習ではうまく見えたのに、採用後に急に崩れるのはなぜか。どこを橋渡しすればよいのか。」とする。

#### Art Director

- recommendation: 見開きの左に実習段階、右に採用後4週間を置き、同じ項目がどう受け継がれるかを線で結ぶ。

#### Web Translator
