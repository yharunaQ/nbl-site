# JAC 重点5フレーム カード見本

更新日: 2026-03-07
状態: card-sample

この見本は、26フレームを `章` として読むのではなく、`カード / フレーム` として一目でつかめる形に寄せた試作です。  
ただし、見出しと箇条書きだけでは理解が浅くなりやすいので、各フレームに `短い具体説明` を入れて、読めば状況が想像できる形にしています。  
また、`関連フレーム` は末尾の参照一覧ではなく、`このフレームを使うとき` とセットで `近いフレームとの見分け方` として示します。

- この文書の主目的は、`重点5カードで内容と誌面の型を先に確かめ、その後26カード全体へ広げること` です。
- したがって、現時点では `独立した最終成果物` ではなく、26カード本体へ進む前の `先行実装プロトタイプ` として扱います。
- ただし、重点論点だけを抜粋して共有したい場面があるなら、将来的に `重点5カード抜粋版` を派生物として切り出すことはできます。
- `3レイヤー` は、26フレーム全体を `体調レイヤー / 就職移行レイヤー / 職場運用レイヤー` で見るための地図です。
- `5つの色や型` は、今回の重点5カード見本で `どう読むと理解しやすいか` を試すための誌面分類です。3レイヤーを置き換えるものではありません。
- つまり、`3レイヤー = 情報構造`、`5つの色や型 = 誌面上の読み分け` です。

## フレーム1 支援接続アーキテクチャ

使える制度が分からないのではなく、`いまどこで止まっているか` が見えていないと支援につながりにくい。

### こんな場面で起きやすい

本人は相談しているつもりでも、企業、JAC、地域支援者、制度窓口のあいだで話が分かれてしまい、同じ説明を何度も繰り返している。誰も何もしていないわけではないのに、次に何が起こるのかが見えず、結果として支援接続だけが遅れていく。

このとき詰まっているのは、制度の数そのものではない。多くは、窓口の順番、期限、責任者、戻り先が一枚で見えていないことにある。

### 鑑別診断 / 問題の切り分け

#### このフレームを使うとき

- 支援制度や相談機関の探索と接続が主課題になっている
- 同じ説明を複数窓口で繰り返している
- 次に誰が動くか、期限がいつか、責任者が誰かが曖昧

#### 近いフレームとの見分け方

- 支援制度・相談機関の探索と接続が主課題なら本カード
- 契約条件や収入見通しそのものの整合が主課題なら `契約収入の安定設計` を優先する
- 実習評価を採用後の運用へ渡すことが主課題なら `実習採用ブリッジ` を優先する

### 具体的な取組み内容

#### 最初にやること

- 本人 / JAC / 就労移行支援事業所 / 企業採用担当 / 自治体窓口を一枚に並べ、`いま止まっている手続き` を1つ丸で囲む
- その場で `3営業日以内に見学候補日を返すのは企業`、`制度要件を一覧化するのは支援員` のように、次の一手の責任者と期限を書く
- 本人へ渡す行動メモは、`今週やること3つ` までに絞る

#### 見落としやすい点

- 制度一覧を増やしても、`見学日調整` や `申請順序` を誰が引き取るかが見えなければ実際の動きは変わらない
- 法域や自治体で条件が変わるので、制度名だけで判断せず、`必要書類` と `期限` まで確かめる

#### 補足して理解したいこと

たとえば、就労移行支援を使いながら応募準備を進めている人でも、`企業見学の日程`、`自治体への確認`、`応募書類の準備` が別々に止まると、本人は動いているのに全体は進まない。このカードは、そうしたバラバラの停滞を1枚に戻すために使う。

このフレームは、制度を覚えるためのカードではない。`支援が止まる場所を見つけて、次の一手を固定するカード` として使うと意味が出やすい。

#### 外部と一緒に考える場面

- 自治体要件の確認、申請順序の整理、同行支援の要否など、企業単独では持ちにくい実務がある
- 窓口間で止まり、`次回いつ誰が連絡するか` が消えそうなときに、地域支援者と一緒に責任線を引き直す

## フレーム2 実習採用ブリッジ

実習でうまくいった条件が採用後に引き継がれないと、採用後に急に崩れやすい。

### こんな場面で起きやすい

実習中は、担当者も周囲も「この人はどの条件なら安定するか」を意識して見ている。ところが採用後は通常運用に戻り、実習でうまくいっていた条件が言葉にされないまま消えてしまう。

その結果、実習では順調だったのに、採用後に急に負荷が上がり、「実習ではできていたのに、なぜ続かないのか」というズレが生まれやすい。

### 鑑別診断 / 問題の切り分け

#### このフレームを使うとき

- 実習評価を採用後運用に接続できていない
- 実習では安定していたのに採用後に急に負荷が上がる
- 初月の担当者、見直し時点、不調時の戻し先が曖昧

#### 近いフレームとの見分け方

- 実習評価を採用後運用に接続できないことが中心なら本カード
- 応募前後の連絡や書類の詰まりが中心なら `応募オペレーション設計` を優先する
- 休職や病休からの復帰初期の戻し方が主課題なら `復職ランプ設計` を優先する

### 具体的な取組み内容

#### 最初にやること

- 実習評価表から、`連続作業時間`、`質問しやすい相手`、`疲れやすい時間帯` など、採用後に持ち込む条件を3つ抜き出す
- 初月1から4週の負荷上限を週ごとに書く。たとえば `1週目は午前中心`、`2週目から電話対応を1件追加` のように段階を刻む
- 不調時の戻し先を、`現場担当 → 人事 → 地域支援担当` の順で固定し、実習で有効だった支援をそのまま採用後の運用表へ移す

#### 見落としやすい点

- 実習担当者しか知らない `声かけのタイミング` や `確認の入れ方` が採用担当へ渡らないと、採用日に橋が切れる
- 評価が高くても、`どの条件なら安定したか` を採用後へ持ち帰らなければ、実習の結果は再現しにくい

#### 補足して理解したいこと

実習で見るべきなのは「できた / できない」だけではない。たとえば `午前中は集中しやすい`、`最初の確認相手が固定されるとミスが減る` といった条件が分かっていれば、それを採用後の勤務表や指導体制に移せる。

`どの条件ならできたか` を採用後へ持ち込んで初めて、実習は橋になる。

#### 外部と一緒に考える場面

- 実習中に使っていた定着支援や同行支援を、採用後の初月にも残したい
- 採用後に負荷が跳ねたとき、実習評価へ戻して `どの条件が外れたか` を地域支援者と一緒に見直したい

## フレーム3 相談運用ガバナンス

相談窓口があっても、`誰が受けるか / 誰が決めるか / どこへ戻すか` が見えていないと調整は遅れる。

### こんな場面で起きやすい

「困ったら相談してください」と言われていても、その相談が業務設計の変更まで届かなければ、本人は話しているのに職場は動いていない、という状態になりやすい。現場、管理者、人事、外部支援の役割が重なったり抜けたりすると、このズレはさらに大きくなる。

相談が遅れる職場では、本人の遠慮や管理者の忙しさだけでなく、責任線そのものが設計されていないことを疑った方がよい。

さらに、相談受付が各管理者に分散し、配慮コストを各チーム予算で抱える設計だと、必要な調整が「その上司が分かるか」「その部署に余力があるか」に左右されやすい。相談の入口と予算の持ち方が分散していること自体が、調整遅延の原因になる。

### 鑑別診断 / 問題の切り分け

#### このフレームを使うとき

- 定期面談やエスカレーションの責任線が曖昧
- 相談はされているのに業務変更まで届かない
- 管理者だけに相談負荷が集中している

#### 近いフレームとの見分け方

- 定期面談・エスカレーション・更新責任がなく配慮運用が続かないなら本カード
- 共有範囲や共有先の設計が主課題なら `情報開示レイヤー設計` を優先する
- 悪化サインへの段階調整手順が主課題なら `悪化予兆ハンドリング` を優先する

### 具体的な取組み内容

#### 最初にやること

- 日々の困りごとは `直属上司`、制度や費用判断は `人事・専門担当`、外部支援接続は `JAC` のように、一次窓口と判断責任者を分けて書く
- `受信確認は24時間以内`、`調整方針は3営業日以内` など、相談から業務変更までの目安日数を決める
- `定型の小さな配慮は現場で即答`、`費用や制度判断が要るものは人事・専門担当へ上げる` など、相談の分岐ルールを先に決める
- `連絡遅延が2回続いたら外部支援へ戻す`、`部署予算で止まりそうなら共通予算や上位決裁へ戻す` など、外部支援と予算判断の戻し先を先に決める

#### 見落としやすい点

- `困ったら相談してください` だけでは、誰も次の判断を引き取らず、相談だけが溜まりやすい
- 管理者が `配慮判断` と `健康情報の管理` を一人で抱えると詰まりやすいので、役割を分ける
- 配慮コストを各チーム予算に閉じると、必要性よりも部署余力で判断が左右されやすい

#### 補足して理解したいこと

相談しやすさの問題に見えても、実際には `話を受けたあと誰が動くか` が決まっていないために遅れることが多い。面談回数を増やすだけでなく、業務変更まで届く線を作れているかを確認したい。

参考にした海外実務では、askEARN の雇用主向けツールキットが、`集中相談窓口` や `集中予算` を持つかどうかを確認項目として置いている。JAN は、雇用主が困った時に戻せる外部の専門相談先として位置づいており、社内の管理者判断だけに閉じない発想を支えている。

このフレームは、面談の雰囲気を整えるためのものではない。`相談が遅れない責任線を作るカード` として使うと焦点がぶれにくい。

#### 外部と一緒に考える場面

- 管理者だけで判断しきれず、ケース会議や定着支援を組み込みたい
- 相談内容が、業務調整だけでなく医療・福祉・就労支援にもまたがり、社内だけでは整理しきれない
- 社内に専門担当や共通予算がなく、難しい事例を JAN のような外部専門相談や地域支援機関へ戻したい

## フレーム4 情報開示レイヤー設計

「全部話す / 何も話さない」ではなく、`何のために / 誰に / どこまで` 共有するかを設計するフレーム。

### こんな場面で起きやすい

配慮を動かしたいので情報は必要だが、話しすぎると本人の不安や二次的な負担が大きくなる。反対に、共有が少なすぎると必要な配慮は動かない。難しいのは、情報の量そのものより、共有目的を決めないまま話が始まってしまうことにある。

このフレームでは、何を隠すかより先に、何のために、誰へ、どこまで共有するのかを整理する。

### 鑑別診断 / 問題の切り分け

#### このフレームを使うとき

- 共有範囲、共有先、更新責任の設計が主課題
- 開示が少なすぎて配慮が動かない
- 開示が多すぎて本人の不安や二次負担が増えている

#### 近いフレームとの見分け方

- 社内運用段階での `共有範囲・共有先・更新責任` の設計が主課題なら本カード
- 採用選考の面接で伝え方そのものが詰まるなら `面接合意形成デザイン` を優先する
- 定例面談やエスカレーション運用が回らないなら `相談運用ガバナンス` を優先する

### 具体的な取組み内容

#### 最初にやること

- 何を共有するかより先に、`朝の立ち上がりに合わせて始業30分を調整するため` のように、共有目的を先に書く
- 情報を `本人だけが持つ`、`管理責任者が持つ`、`チーム共有する` の3層に分け、どの情報がどこまで必要かを決める
- 共有先ごとに、目的、記録責任、見直し時点を書く。たとえば `実習終了時に見直す`、`初月2週目で更新する` など時点まで置く

#### 見落としやすい点

- 病名や通院歴まで共有しても、配慮実装に必要な情報でなければ現場はかえって扱いに困る
- 法域差があるので、健康情報や個人情報を `チーム共有メモ` に広げる前に、目的と制度条件を確認する

#### 補足して理解したいこと

たとえば、`週の後半に疲労が強まりやすいので木曜午後は確認回数を増やす` という情報なら、チーム共有で足りることが多い。一方、診療内容の詳細は、配慮実装に不要なら共有しない方が安全である。

このフレームの主役は病名ではなく `共有目的` である。本人だけが持つ情報、管理責任者が持つ情報、チーム共有する情報を分けると、話すべきことが整理しやすい。

#### 外部と一緒に考える場面

- 本人が `話しすぎてしまう不安` や `話さなさすぎて配慮が動かない不安` を持っていて、企業内だけで線引きしづらい
- 必要配慮はあるが、どの情報を共有せずに済ませられるかを地域支援者と一緒に整理したい

## フレーム5 悪化予兆ハンドリング

危機対応だけでなく、`初期サイン → 段階調整 → 再評価` の戻り道を先に持つフレーム。

### こんな場面で起きやすい

不調が重くなってから慌てて対応する職場では、その前に小さな変化が出ていても、「まだ大丈夫」と流されていることが少なくない。連絡が遅れる、作業の立ち上がりが鈍る、休憩後も戻りにくい。こうした変化を誰も `調整の入口` として扱えていないと、対応は重くなりやすい。

このフレームで整えたいのは、危機対応そのものより、早い段階で戻せる仕組みである。

### 鑑別診断 / 問題の切り分け

#### このフレームを使うとき

- 悪化兆候の定義や連絡手順がない
- 小さな変化を流したまま、対応が遅れやすい
- 緊急時の共有範囲や戻し先が曖昧

#### 近いフレームとの見分け方

- 悪化兆候の定義や連絡・負荷調整手順の不在が中心なら本カード
- 日常的な体調波全般のペーシングが主課題なら `体調変動マネジメント` を優先する
- 相談責任線が曖昧で、情報が上に上がらないことが主課題なら `相談運用ガバナンス` を優先する

### 具体的な取組み内容

#### 最初にやること

- 初期サインを、`返信が半日以上遅れる`、`朝会で発言が減る`、`休憩後に戻りにくい` のような観察できる言葉に置き換える
- サインごとに段階調整を決める。たとえば `2回続いたら当日の業務量を2割減らす`、`週内に2回出たら翌週の会議で再評価する` のように閾値を書く
- 緊急時だけでなく、再評価まで含めて戻り道を書く。`直属上司 → 人事 → 地域支援担当` の順で誰に戻すかを明記する

#### 見落としやすい点

- 救急レベルの手順だけ整えても、軽い悪化で戻す導線がないと対応は毎回重くなる
- 初期サインを `本人の頑張り不足` と見てしまうと、連絡も調整も遅れやすい

#### 補足して理解したいこと

たとえば、欠勤してから相談するのでは遅い。`連絡が遅れる`、`締切直前の焦りが増える`、`休憩後に戻りにくい` といった小さな変化を入口にして、早い段階で業務量や確認頻度を調整できる方が実務では使いやすい。

このフレームは `悪くなったときのカード` ではなく、`悪くなる前に戻すカード` として見る方が使いやすい。

#### 外部と一緒に考える場面

- 連絡遅延や欠勤前兆が2回続き、社内だけの調整では戻しにくくなってきた
- 再評価や定着支援の導線を最初から入れて、悪化時に `誰へ戻すか` を明確にしたい

## この形で確認したいこと

- タイトルだけで、そのフレームの中身が想像しやすいか
- タイトル直下の補足説明で、`何のカードか` がすぐつかめるか
- `近いフレームとの見分け方` を見ると、鑑別診断のように選び分けられるか
- `具体的な取組み内容` を見ると、相談や実装の入口が分かるか
- 長い章より、カードとして並んでいる方が使いやすいか
