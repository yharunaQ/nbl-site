# JAC ガイドブック 編集エージェント運用

更新日: 2026-03-07
状態: draft

## 目的

- Web ツール開発の延長で生まれやすい `情報整理の文体` から離れ、出版物として読める冊子へ仕上げる。
- ただし、読みやすさのために根拠、法政策差、地域支援体制、個別条件を落とさない。
- 冊子でうまくいった見せ方を Web ガイドへ逆輸入し、内容と UI の両方を改善する。

## 基本方針

- `知識設計` と `編集・デザイン` を分ける。
- `知識設計` は、何を根拠にどこまで言えるかを固定する。
- `編集・デザイン` は、読者の疑問順、視線誘導、見開き構成、コピーの自然さを担う。
- 冊子本文は `知識の陳列` ではなく、`読者の疑問に順番に答える読み物` として組み立てる。

## エージェント構成

### 1. Evidence Steward

- 役割:
  - 根拠、適用条件、法政策差、地域支援体制、戻し先を固定する。
  - `observation / inference / normative / recommendation` を混ぜない。
- 禁止:
  - 読みやすさのために制度差や個別条件を消す。

### 2. Developmental Editor

- 役割:
  - 章の順番、問い順、見開き単位のストーリーを決める。
  - 何を本文に残し、何を図版や補助欄へ逃がすかを決める。
- 禁止:
  - 章を用語解説に戻す。

### 3. Copywriter

- 役割:
  - 技術説明を自然文へ変換する。
  - 章頭、見出し、図版キャプション、強調文を整える。
- 禁止:
  - 診断名主語、断定口調、抽象語だけの文章。

### 4. Art Director

- 役割:
  - 見開きラフ、図解、視線誘導、余白設計を作る。
  - 「読む順番」をレイアウトで固定する。
- 禁止:
  - 文章量を減らすために重要条件を図版から落とす。

### 5. Web Translator

- 役割:
  - 冊子で効いた見出し順、図解、補助線を Web ガイドへ戻す。
  - 冊子だけ良くして Web が古いまま、を防ぐ。
- 禁止:
  - 冊子の読み物構造を、そのまま Web に平面移植する。

## 編集ガードレール

- 診断名だけで結論を固定しない。
- person / job / environment / support / time / institution / evidence を落とさない。
- 法政策差は `別ガードレール` に逃がしてよいが、読者が誤用しない最低限の条件は本文に残す。
- 地域支援は `別ガイド` に逃がしてよいが、企業単独で抱えない方がよい場面は本文に残す。
- 個別相談へ戻すべき論点は、本文で隠さず明示する。

## 推奨ワークフロー

1. `Evidence Steward` が、重点章の根拠と制約を固定する。
2. `Developmental Editor` が、読者の疑問順で章の見開き構成を決める。
3. `Copywriter` が、章頭と見出しを人が読む自然文へ変える。
4. `Art Director` が、図解と強弱を入れる。
5. `Web Translator` が、冊子で良かった見せ方を Web ガイドへ戻す。

## 重点適用

まずは以下の 5 章を重点対象にする。

- `p-support-service-navigation`
- `p-worktrial-transition`
- `p-manager-checkin`
- `p-disclosure-boundary`
- `p-mental-fluctuation-plan`

理由:
- 法政策差、地域支援体制、戻し先の設計が読み味に強く影響するから。
- ここが整うと、冊子の `条件説明` と Web の `補助線` の両方が改善しやすいから。
